# M19 — T0 액션 판(action plate)과 텍스트 위계: 전역 표현 계약

> **이 문서가 무엇인가**: T0Interface가 그리는 **모든 버튼 한 종류**와 **텍스트 역할 3종**의
> 표현(presentation) 계약이다. 기존 런타임 승인된 M7 UI 스킨 색과 코드 UI 프리미티브만 재사용한다.

같은 사이클 안의 제자리 추가다 (RFC-Q2: `cycle` 값 불변 → `supersedes: null`, 아카이브 의무 없음).

사용자 요청 원문: "버튼유아이랑 텍스트 유아이 게임스럽게 개선" (2026-09-13).

## 1. 시각 약속 (the exact visual promise)

[TARGET] 플레이어가 얻는 것은 **한 문장**이다:
"이 화면의 조작 대상은 넓은 어두운 사각형이 아니라, **눌릴 수 있는 계기 판(instrument plate)** 이고,
지금 내가 고른 판은 **한눈에 구분된다**."

관측 가능한 형태로 쪼개면 네 가지다.

| # | 약속 | 어떻게 보이는가 |
|---|---|---|
| P1 | **행동 가능성(affordance)** | 모든 액션 판의 왼쪽에 황동(brass) **눈금 막대(rule)** 가 서고, 위쪽에 황동 **모서리 선(bevel)** 이 얇게 들어간다. 넓은 평면 사각형이 "테두리와 눈금을 가진 판"으로 읽힌다 |
| P2 | **선택/포커스 상태** | 고른 판은 **판 자체가 황동으로 반전**되고 라벨과 눈금이 어두운 잉크색으로 뒤집힌다. 어두운 판 위의 어두운 틴트가 아니라 **명암이 반대**가 되므로 배경과 섞이지 않는다 |
| P3 | **비활성 구분** | 비활성 판은 눈금 막대가 **사라지고** 판이 흐려진다. "누를 수 있음"의 표식이 물리적으로 없다 |
| P4 | **텍스트 위계 3단** | 본문(읽을 것) · 액션 라벨(누를 것) · 보조 설명(참고할 것)이 **크기 · 굵기 · 색조** 세 축으로 동시에 갈린다 |

- 감정 목표: 화려함이나 연출 고조가 아니라 **기록 계기(archival instrument)** 의 침착한 조작감.
  금속 눈금과 종이, 두 가지 재질만으로 읽힌다.
- `immersion_target`: 측정하지 않는다(N/A). 이 조각은 몰입 연출 타임라인이 아니라 조작면 표현이다.
- 애니메이션·전환 타이밍을 **추가하지 않는다**. 색 전환 지연은 0으로 두어 상태가 즉시 읽히게만 한다.

### 1.1 텍스트 역할 표 (P4의 정확한 값)

| 역할 | 이전 | 이후 | 굵기 | 색조 |
|---|---|---|---|---|
| 본문 (body) | 20 | **20 (불변)** | Normal | `ink` / `paper` (불변) |
| 액션 라벨 (action label) | 17 | **18** | **Bold** | `paper` (불변), 선택 시 `ink` 반전 |
| 보조 설명 (contextual helper = `ViewAction.Detail`) | 17 | **16** | Normal | **약화 색조** (배경 쪽으로 0.32 보간) |
| 제목 / 부제 / 상태 / 푸터 / 사건 카드 / 차트 라벨 | 28 / 15 / 16 / 13 / 20 / 15 | **전부 불변** | 불변 | 불변 |

[OBSERVED] 이전에는 **액션 라벨과 보조 설명이 둘 다 17** 이어서 "누를 것"과 "참고할 것"이
같은 무게로 보였다. 이후에는 `18 Bold` vs `16 Normal 약화색`으로 갈린다. 본문 20은 건드리지 않아
읽기 흐름의 기준선이 유지된다.

### 1.2 근거가 되는 실측 결함 [OBSERVED]

이 계약은 취향 선언이 아니라 두 개의 **코드 경로 결함**을 겨냥한다.

1. `Button()`이 만드는 판은 `Panel(action.Id,…,ink)` — 테두리·눈금·모서리가 **하나도 없는** 단색
   `ink` 사각형이었다. 관측된 "넓고 평평한 어두운 액션 사각형"의 직접 원인이다.
2. 선택 색이 삼켜졌다. Unity `Selectable`의 색 전환은 대상 그래픽 색에 **곱셈**으로 적용된다.
   `selectedColor = brass(.73,.56,.28)` × `Image.color = ink(.1,.18,.2)` = `(.073,.101,.055)` —
   즉 선택하면 판이 **더 어두워졌다**. 정점 색은 `Color32`로 클램프되므로 곱셈으로는 **밝아질 수
   없다**. 그래서 P2는 곱셈 틴트가 아니라 **판 색 자체의 반전**으로 구현해야 한다.

## 2. 리소스 재사용 (새 에셋 0건)

| 재사용 대상 | 경로 | 방식 |
|---|---|---|
| M7 UI 스킨 색 | `Resources/M7UiSkin.asset` (`ink` `paper` `brass`) | `Render()`가 **이미** 해석해 둔 `ink`/`paper`/`brass` 지역 값을 그대로 읽는다. 신규 필드 0건 |
| M7 스킨 텍스처 | `M7_*_basecolor` (paper/bronze) | `SkinBacking()` 기존 배선 그대로. 버튼에 텍스처를 **새로 붙이지 않는다** |
| 코드 UI 프리미티브 | `UI/T0Interface.cs` (`Rect` / `Panel` / `Text` / `FlowText` / `Button` / `FocusSelection`) | 합성만 한다. 신규 위젯·프리팹·셰이더·스프라이트·머티리얼 0건 |
| 비-raycast 장식 선례 | 같은 파일 `SkinBacking()` | 장식은 `raycastTarget=false` 자식이라는 기존 규칙을 그대로 따른다 |

**금지 사항 (이 계약이 스스로 묶는 것)**

- `M7UiSkinProfile` 의 필드·기본값·`runtimeApproved` 를 **바꾸지 않는다**. 승인 게이트는 그대로다.
- 2D/3D/이미지/영상 **생성·구매 0건**. `assets/generated/**` 및 `provenance.json` 무변경.
- `runtimeEligible` / `runtimeApproved` 승격 **0건**.
- 게이트 OFF(스킨 미승인) 경로에서도 동일한 판 형태가 나오도록 **커밋된 리터럴 색만** 쓴다.
  즉 M19는 스킨 승인 여부와 **무관하게** 작동하며, 스킨 리터럴 계약(M7UiSkin 테스트)을 깨지 않는다.

## 4. 구현 경계 (한 개의 전역 슬라이스)

- 수정 지점은 `UI/T0Interface.cs` 의 **`Button()` 한 곳 + 텍스트 역할 3개 호출 지점 + `FocusSelection`
  의 해제 콜백**뿐이다. 화면별 분기·화면별 예외를 만들지 않는다 → 타이틀/허브/판독기/회로/서명지/
  오버레이/툴바/내비게이션의 **모든 버튼이 같은 규칙**을 받는다.
- 신규 상태 기계 0개. 선택 반전은 기존 `ISelectHandler`에 대칭되는 `IDeselectHandler` 하나로 닫는다.
- 장식 오브젝트는 버튼 루트의 자식 2개(`Bevel`, `Rule`)뿐이다. 루트에는 `LayoutGroup`이 없으므로
  자식 추가가 기존 자식(`Label`, `Hold progress`)의 배치를 밀어내지 않는다.

## 5. 수용 기준 (자동 검사 가능한 형태)

1. 활성 액션 판마다 `Rule`(활성) · `Bevel` 자식이 존재하고 **둘 다 `raycastTarget == false`**,
   루트 `Image.raycastTarget == true`.
2. 비활성 액션 판은 `Rule`이 **비활성(`activeSelf == false`)**.
3. 포커스된 판의 배경색과 라벨색이 비포커스 판과 **반전**되어 있고, 배경 상대휘도 차이가
   측정 가능한 임계 이상이다. 포커스를 옮기면 반전도 따라 이동한다.
4. `colors.selectedColor`가 더 이상 판을 어둡게 곱하지 않는다(= 흰색), 전환 지연 0.
5. 텍스트 위계: `본문 fontSize > 라벨 fontSize > 보조 fontSize`, 라벨만 `Bold`,
   보조는 `Normal` 이며 본문색과 다른 약화 색조.
6. §3의 N1–N12 중 자동 검사 가능한 항목(액션 ID·순서·활성·라벨 문자열·포커스 수·배율 1.5 리플로)이
   모두 불변임을 같은 테스트가 단언한다.

## 6. 대비 수치의 지위 (주의)

[OBSERVED] 이 계약이 쓰는 조합의 sRGB **평면 색 상대휘도 산술값**:

| 조합 | 계산값 |
|---|---|
| 비선택 라벨 `paper` on `ink` | 약 11.2:1 |
| 선택 라벨 `ink` on `brass` | 약 4.8:1 |
| 보조 설명(약화) on `paper` | 약 4.6:1 |
| 본문 `ink` on `paper` | 약 11.2:1 |

**이 숫자들은 인증이 아니다.** 평면 색끼리의 공식 대입 결과이며, (a) 아래 깔린 M7 넝마지·청동
텍스처, (b) 글리프 안티에일리어싱과 한국어 획 두께, (c) 실제 디스플레이 감마·밝기를 반영하지
않는다. 따라서 **WCAG 등 어떤 접근성 표준의 적합·인증도 주장하지 않는다.** 이 표는 "선택 상태가
배경과 섞이지 않는다"는 §1.2 결함 수정의 방향 근거일 뿐이며, 실측 대비·가독성 검증은
미측정(NOT-MEASURED) 항목으로 남는다.

## 7. 비목표 (explicit non-goals)

1. **최종/출시 아트가 아니다.** 프로그래밍 도형 2개로 만든 표현 기초이며, 아트 디렉션 확정도
   비주얼 레인 산출물의 대체도 아니다. 후속 스프라이트/9-슬라이스/셰이더 작업을 전제하지 않는다.
2. **접근성 인증이 아니다.** §6 참조. 기존 텍스트 배율·저감모션 설정을 상속만 한다.
3. **새 기능·새 정보가 아니다.** 표시되는 내용·순서·가용성은 §3 그대로 불변이다.
4. **사람 플레이테스트 n=0, 성능 측정 0건.** 프레임 시간·GPU·발열 주장 없음.
5. **M7 리소스 승격이 아니다.** 승인 플래그·프로필 값 무변경.
6. **연출 타임라인 추가가 아니다.** 새 전환·새 컷·새 카메라·새 사운드 큐 0건.
7. 게이트 이동 0건. G4 `NOT-MEASURED` 유지, `status: draft` 유지(§0).
