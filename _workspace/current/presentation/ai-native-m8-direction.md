# M8 연출 — 검토 노트에서 다음 관측으로

[TARGET] M7의 바다 수평선·젖은 금속·회백 종이·원형 판독기와 같은 작업대에서, 플레이어의 **미확정 생각**을 잠시 펼친다. 출처를 연결하고 질문 하나를 들고 다시 물리 도구로 돌아가는 흐름이다. 대화 상대나 전지적인 기록국 AI를 추가하지 않는다. 게임 내 이름은 `검토 노트`, 행동은 `출처 연결`·`검토 질문 보기`·`메모 보관`으로 제안한다.

[TARGET] 본 문서는 M7에 더하는 UX/연출안이다. 원본 컨셉과 승인된 M7 계보만 시각 기준으로 쓰며 현재 프리팹·런타임 화면을 참조하지 않았다. 미래 구현 목표이고 현재 조작 영상의 증거가 아니다.

## 구현 대조와 연출 목표 구분

[OBSERVED · 코드 열람] `ReviewNotesSession.cs`·`ReviewNotesStore.cs`·`T0ReviewNotesInterface.cs` 기준으로 현재는 여러 줄 메모 입력·출처 연결 토글·별도 보관·출처 구조 기반 질문 설명을 제공한다. 아래 화면·초점·타이밍 명세는 그 위에 남아 있는 연출 목표를 포함한다.

- 명시적 질문 요청 버튼은 아직 없다. 현재 `review-note-question`은 비활성 정보 항목이며 화면 재구성 시 질문 설명이 갱신된다.
- 출처 선택은 연결 토글이다. 현재 뒤로 가기는 자료 검토 화면을 열고, 편집 종료는 메모 보관/편집 항목으로 초점을 옮긴다. 아래의 원문 열기·특정 출처/직전 도구로 정확히 복귀하는 흐름은 TARGET이다.
- IME 조합 활성 여부와 Enter/Tab/Escape를 구분하는 방어 코드는 있지만, 실제 한글 OS IME·물리 컨트롤러 검수 완료를 의미하지 않는다.
- 아래 180/100/120/140ms 전환과 reduced-motion 0ms는 저작 목표다. 이 세 파일에서 해당 타이밍 연출 구현을 확인하지 않았으며 실측도 하지 않았다.

## 화면 구조와 입력

| 영역 | 내용 | 행동 |
|---|---|---|
| 내 가설 | 편집 가능한 문장과 작은 `미확정 메모` 표기 | 글을 쓰거나 빈 채로 둔다. 자동으로 새 문장을 완성하지 않는다. |
| 연결한 출처 | 이미 확인한 자료의 공개된 이름·매체 실루엣·같은 원본 관계 | 자료를 선택·해제하고 원문으로 돌아간다. 내부 식별자는 표시하지 않는다. |
| 검토 질문 | 출처 관계 요약과 질문 하나 | `검토 질문 보기`를 눌렀을 때 갱신. 입력마다 말풍선/알림을 만들지 않는다. |

[TARGET] 클릭한 출처는 원문을 살필 수 있도록 같은 작업대의 보조 보기에 연결한다. 빈칸은 실패나 오류가 아니다. 필요한 문장은 선택적으로 적으며, 컨트롤러는 자료 선택과 질문 확인만으로 같은 흐름을 사용할 수 있다. 텍스트 입력을 필수 퀘스트 조건으로 만들지 않는다.

[TARGET] 초점 순서는 가설→출처 목록→검토 질문 보기→질문→메모 보관/닫기다. 질문 갱신이 입력 초점을 빼앗지 않는다. 한글 IME 조합 확정 Enter는 검토·보관·게임 확정으로 전달하지 않는다. 여러 줄 문장의 Enter와 UI 활성화 입력을 구분한다. 원문 보기를 닫으면 선택했던 출처로, 노트를 닫으면 직전 작업 도구로 돌아간다.

## 타이밍과 감각

```yaml
scene: m8-reflection-note
status: target
intent: 내 생각을 판단받기보다 근거를 직접 다시 살펴볼 여유를 느낀다.
immersion_target: 3
beats:
  - at_ms: 0
    event: 플레이어가 검토 노트를 연다. 현재 공개된 출처 목록만 만든다.
  - at_ms: 0
    duration_ms: 180
    event: 회백 종이 패널이 나타난다. 도구와 바다의 배경 위치는 유지한다.
  - trigger: 출처 선택
    duration_ms: 100
    event: 선택 윤곽과 공개된 매체 표기를 바꾼다. 정답/성공 빛은 없다.
  - trigger: 검토 질문 보기
    duration_ms: 120
    event: 구조 요약과 저작 질문 하나를 교체한다. 가짜 타이핑/생각 중 연출은 없다.
  - trigger: 닫기
    duration_ms: 140
    event: 노트를 닫고 직전 도구에 초점을 돌려준다.
camera: 도구 조작을 가리지 않는 작업대 보조 패널. 자동 카메라 이동/줌 없음.
audio_cue: 열기·닫기의 작은 종이 소리만 선택적으로 사용. 입력 키마다 소리를 내지 않는다.
vfx_ref: m8-note-selection-outline — 색과 선형/문자 동시 사용, 성공 파티클 없음.
anim_ref: m8-note-open-close — 종이 패널의 짧은 표시/퇴장, 인물/손 애니메이션 필수 아님.
motion_ref: m8-focus-return — 초점 유지와 복귀; reduced-motion이면 모든 전환 0ms.
```

[TARGET] 위 숫자는 UI 전환 목표이며 실제 처리시간·가독성 측정치가 아니다. 질문 수신에 성공 팡파르·봉인·새 구역 개방 연출을 붙이지 않는다. 사용자가 메모를 보관했을 때 작은 `메모 보관됨` 상태만 제공하며 기존 게임의 확정 저장 표현과 구분한다.

## 단계 공개 규칙

| 시점 | 보여줄 수 있는 것 | 유지할 경계 |
|---|---|---|
| 처음 노트를 열 때 | 기능의 한 줄 설명과 현재 직접 확인한 자료 | 미발견 자료의 이름·수·실루엣·정답 대상 미리보기 없음 |
| 같은 원본 자료를 연결했을 때 | 현재 선택한 자료들의 출처 중복 | 보이지 않는 독립 단서를 이름/위치로 추천하지 않음 |
| 다른 매체를 연결했을 때 | 대조할 관계와 반증 질문 | 옳다는 판정, 새 사실, 다음 장 진실을 제공하지 않음 |
| 가설에 이후 사건/명령을 직접 썼을 때 | 플레이어가 쓴 문장 그대로 | 시스템이 이를 사실로 인정하거나 연출/권한을 실행하지 않음 |
| 기존 게임이 다음 단계를 공개한 뒤 | 새로 열람한 자료를 사용자가 선택한 경우 | 노트 자체가 공개 단계나 이동을 발생시키지 않음 |

[TARGET] 질문은 `이 생각은 직접 본 어떤 관측에서 시작됐나요?`·`같은 원본에서 나온 것은 아닌가요?`·`이 해석과 맞지 않는 관측은 없었나요?`처럼 생각의 방법을 묻는다. 특정 자료와 조작 값을 알려주는 것은 기존 힌트에서 플레이어가 그 단계를 직접 열었을 때의 책임이다. 노트에 그 우회 경로를 만들지 않는다.

## GTI 미래 자원 연결

[TARGET] 제작 순서는 **세계관·원본 컨셉 → M7 연출 영상의 채택 방향 → GTI 후속 자원 → 새 프리팹**으로 유지한다. 이번 코드 대조는 기능/입력 동작만 살폈으며 현재 UI나 프리팹의 시각 형태를 새로운 아트 기준으로 삼지 않는다.

| 새로 필요한 조각 | M7/원본 기준 | GTI 생성과 후속 저작 분리 |
|---|---|---|
| 검토 카드 바탕 | 당직실의 회백 종이와 `M7-PROP-record-set` | 글자 없는 종이섬유·접힌 모서리 자료. 가설·상태·출처명은 런타임 텍스트로 저작. |
| 매체 표식 3종 | 원본의 염판·실제본 일지·긴 조위대장 실루엣 | 원본 계보로 실루엣 시트를 설계. 선택/초점/같은 원천 표식은 별도 UI 도형. |
| 낮은 거치 프레임 | 당직실 기록 거치대와 마모 청동 | 반사광을 굽지 않은 마모/녹청 자료. 실제 UI 대비와 크기는 구현 후 검수. |
| 미확정 연결선 | 기존 종이·클립의 절차적 느낌 | 연결선·화살표는 수동 벡터 저작. 생성 무늬를 증거 또는 정답 연결로 사용하지 않음. |

[TARGET] 새 이미지 생성 시 god-tibo-imagen을 사용하고 원본 컨셉/M7 승인 파생물의 해시 계보를 남긴다. 현재 모델·프리팹·런타임 텍스처를 재입력하지 않는다. GTI 산출물은 후보이며 글자·증거·체크표시·숫자를 생성 이미지에 굽지 않는다. 생성/권리/가독성 검수 없이 runtime 자격을 부여하지 않는다. 이 작업에서는 생성하지 않는다.

## 검수 관점

[TARGET] 실제 캡처에서 패널 전환·IME 입력·초점 복귀·화면 축소 시 글자 겹침·저모션을 확인한다. 자료 연결 전후에도 저장/확정/단계 공개 상태가 그대로인지 별도 기능 검사한다. 사람이 가설을 더 잘 설명하거나 다른 근거를 다시 살폈는지는 플레이테스트로 평가한다. 질문 출력만으로 추론 정확도나 몰입 개선을 주장하지 않는다.
