## 결론

**R1/R2/R3/R5/R7 구현과 R4 계약 교정을 마쳤다.** 초기35ebdc5의 S2 다섯 건과5d7b18c의 후속6건(S2 5·S3 1)에 더해, 같은 Q6의 판독기 밖 재발 경계도 교정했다. 최신 Unity 프로젝트 고유187개 통과와 macOS 네이티브를 확인했다.177/186개 및 이전 캡처는 각 빌드의 역사로 남긴다.

## 디버깅과 리뷰 결과

ReaderCompare·SignatureSources·AlignmentPractice·CanonConsistency가 소유권/목표를 ACK했고 GoalReview가 반례를 검토했다. 통합 후 RuntimeAcceptance/EvidenceAcceptance는 읽기 전용으로 구현을 재검토했다. 빌드·테스트·네이티브 입력은 Main만 실행했다.

1. **Q1:** 같은 화면 revision의 연속 자동저장에서 최신 실패가 숨겨졌다. 쓰기 sequence와 표시 revision을 분리하고 최신 실패는 화면 변화로 버리지 않는다.
2. **Q2:** 실제 화면 Back으로 미리보기를 닫아도 Preview가 남았다. 공통 종료 처리로 해제하되 더 늦은 SaveFailed는 보존한다.
3. **Q3:**150%에서 연습장 하단 설명에 키보드 경로가 없었다. 페이지 위/아래를 기존 Navigation과 ScrollRect에 연결하고 재렌더/초점 리셋을 피했다.
4. **Q4:** 확정 대기를 취소한 뒤 no-op Redo가 작업 저장을 재소유하지 않았다. 취소 여부에 따라 변경본 또는 현재 작업본을 다시 저장한다.
5. **Q5:** 실제 깊은 C1 근거 목록에서 작업저장 문구가 화면 밖으로 사라졌다. 고정 오른쪽 저장 영역으로 옮겼다. 처음 Navigation까지 줄인 안은 기존150% Band comparison 회귀를 실패시켜 폐기했고, 작업면만 줄인 최종안으로 통과했다.
6. **Q6:** 앞 비트에서 읽은 표준판이 유지된 채 Undo로 대장 접근이 사라져도 고정 대장이 남았다. 매 렌더의 출처 가시성 검사로 해제하고 Redo에 자동 재고정하지 않는다.
7. **Q7:** StartGame/OpenReviewNotes/SetConfirmMode/SaveReviewNoteAsync/합법 ContinueToPatrol/ContinueToSignature가 연습장을 먼저 벗어나거나 파일을 썼다. 각 진입점의 첫 검사로 차단했다. 기존 OpenOverlay/OpenInterviewPrep 및 일반 진행의 합법성은 보존했다.
8. **Q8:** 대응 설명의 별도 이름이 M21 Text 읽기 배경에서 빠졌다. 기본 Text 식별자를 복원했다.
9. **Q9:** 실제 진단 화면에서 비교 카드와 CaseThread의 검은 글씨/선이 어두운 작업면에 묻혔다. 그 중첩 영역에만 비입력·반투명 배경을 두고 의미 이름/색/기본 스킨을 보존했다.
10. **Q10:** 진단 연습 트랙과 A/B 라벨에도 같은 배경 누락이 있었다. 부모 카드로 Graphic/CanvasRenderer를 분리하고 실제 mesh의 불투명 획 대비까지 검사했다.
11. **Q11 · S3:** 대비 복원 뒤 첫 wide/마지막 shoulder 피크 일부가 잘리는 것이 드러났다. 실제 mesh 정점이 왼쪽 경계를4.48단위 넘는 RED를 얻고, 양 모드의 가로 여백을4%로 늘려 끝 모양을 보존했다.

초기 정적 리뷰의 “추가 입증 결함 없음”은 당시 담당 범위의 결과였고, 이후 Q6–Q11이 발견됐다. 후속 PracticeIsolationFix/PracticeContrastFix는 분리된 회귀 파일과 패치 제안을 맡았으며 Main이 RED·적용·전체 실행·네이티브를 수행했다. 실제 세션 API 경계 검증이지 Initialize/직접 Journal 객체 변조에 대한 sandbox 증명은 아니다. pending 화면 닫기는 쓰기를 계속하고 Esc/Undo는 취소하는 기존 구분을 유지한다.

추가 Q6 반례: Ledger pin→회로 지도→접근 상실까지 Undo→회로에서 Redo→판독기 재진입 시 extra Ledger가 남았다. `ClearUnavailableReaderPin()`을 공통 `Render()`의 초기화 검사 직후로 옮겼다. 신규1사례 RED→GREEN과 native112–117을 확인했다. 같은 결함의 미포함 경계이므로 새 결함 id/개수를 만들지 않는다.

## 소스 전달 경계

이번 사용자 요청은 명시적 경로 stage/commit/일반 push를 승인했다. 단일 main의 기존 M14–M22 런타임·리소스·Aside 조사 작업은 현재 빌드 의존성/출처이므로 보존한다. 새 작업으로 위장하거나 미승인 아트의 runtimeEligible/commercial 상태를 승격하지 않는다. 삭제·force push·설치·유료 생성·사람 자료 공개는 하지 않는다. 정확한 전달 커밋과 원격 반영 결과는 Git 기록/최종 응답으로 보고한다.

[DELIVERY POLICY] 기존 M14–M21/Aside 기준선의 원시 `.log`53개는 변경 없이 로컬에 보존하고 이번 stage에서 명시 제외한다. 실행 XML·해시/요약·리소스 출처는 전달한다. 로컬 로그 링크를 공개 사본이 존재한다는 뜻으로 읽지 않는다. M23 신구 실행/부정 증거는 선별된 JSON/XML/스틸로 전달한다.
