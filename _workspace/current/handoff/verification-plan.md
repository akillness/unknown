# T0 검증 계획 — 사람 검증 프로토콜 · 성능 캡처 · G4/G5/G6/G7 측정 방법

> 이 문서는 **어떻게 재는가**를 정한다. **무엇 하나도 아직 재지 않았다** — 사람 표본 n=0 · 빌드 0회 · 프레임타임 캡처 0건 [OBSERVED 2026-09-10].
> 코드 완료(DoD, `codex-unity-brief.md` §⑩-3)는 이 문서의 **시작 조건**이지 통과가 아니다.
> 계획을 세웠다는 사실이 게이트를 올리지 않는다.
>
> **본 생산 착수 조건은 이 문서가 정하지 않는다** `[C6-F9 · 2026-09-10 R7 종료]`. 정본은 `production/premium-preproduction-contract.md` 「## Base production gate」 **한 절뿐**이며 이 계획은 그 절이 요구하는 **① T0 사람 검증 H-1~H-3** 의 재는 방법을 제공할 뿐이다. 나머지 세 조건(조위정합 스파이크 개념 검증 · **소요 150% 초과 시 STOP** · 열린 S1 0 · G8 exit 0)은 이 문서 밖에서 판정된다. 조건을 여기 다시 적어 네 번째 사본을 만들지 않는다.

## 0. 이 계획이 답하는 질문과 답하지 않는 질문

| 답한다 | 답하지 않는다 |
|---|---|
| T0 25분 슬라이스가 **처음 만난 사람에게 스스로 설명되는가** | 본편 480분이 재미있는가 |
| 두 도구(`circuit` · `reader`)의 **조작이 이해되고 진행 가능한가** | `alignment`·`routing`·`corrosion`·`seal` 의 조작감(별도 스파이크 필요) |
| 저장·복구·되돌림이 **실패 상황에서 사람을 잃지 않는가** | 상업적 성공·판매량·위시리스트 |
| 성능 목표를 **어떤 기준으로 재게 될 것인가** | 성능이 목표를 만족하는가(**기준 하드웨어 미정**) |

**T0 25분 측정치로 8시간(480분)을 주장하지 않는다.** 두 수치는 다른 대상이다.

## 1. 사람 검증 프로토콜 — 12명 / 5유형

### 1.1 표본

| 항목 | 값 | 근거 |
|---|---|---|
| 최소 인원 | **12명** | 계약 「Time acceptance」 · `telemetry-contract.md` §1.2 |
| 유형 | **5유형**으로 균형 모집: ① 초보(퍼즐·추리 게임 경험 적음) ② 추리 숙련 ③ 도구 조작 선호 ④ 서사 선호 ⑤ **접근성 요구**(키보드 전용 · 홀드 곤란 · 색각 이상 · 자막 필요 중 하나 이상) | `product/assumption-tests.md` |
| 중복 계상 | **금지.** 한 참가자를 두 유형으로 세지 않는다 | 동상 |
| 탈락 | **탈락도 보고한다.** 완주자만 보고하는 표는 무효 | `telemetry-contract.md` §1.2 |
| 공략 | **금지.** 공략·힌트 문서를 보지 않은 초회 플레이만 유효 | 동상 |
| 동의 | 익명 ID + 최소 플레이 이벤트만 보관. 사전 고지 후 수동 수집 | `telemetry-contract.md` §0 |

**접근성 유형(⑤)을 채우지 못하면 그 회차는 "12명 달성"이 아니다.** 인원만 채우고 유형을 비우는 것은 표본 위장이다.

### 1.4 AFK 회고 판별 (자동 제외 금지)

| 규칙 | 내용 |
|---|---|
| A-1 | 코드는 60초 이상 무입력 구간을 `afk_gap` 으로 **기록만** 한다. `verdict` 는 수집 시점에 **항상 `null`** |
| A-2 | 세션 종료 후 관측자가 각 후보 구간을 참가자에게 제시하고 **"자리를 비웠습니까 / 생각 중이었습니까"** 를 묻는다 |
| A-3 | 답을 `afk_review: [{gap_index, verdict: away\|thinking\|unknown}]` 으로 원본과 함께 보존한다 |
| A-4 | **`unknown` 은 자리비움으로 치지 않는다**(보수적으로 시간에 남긴다) |
| A-5 | `afk_total_min` = `verdict == away` 인 구간의 합. `total_minus_afk_min` = `total_min − afk_total_min` |
| A-6 | **회고를 하지 않은 세션은 `afk_total_min = null` 이고 `total_minus_afk_min` 도 `null` 이다.** 그 세션은 판정 표본에 넣지 않고 "미회고"로 별도 보고한다(탈락으로도 세지 않는다) |
| A-7 | 마우스 이동·스크롤·패널 열기도 **유효 입력**으로 센다. 생각 시간은 자리비움이 아니다 |

### 1.5 수집 키 (빌드가 기록해야 하는 것)

`beat_reached` · `beat_completed` · `stage_completed` · `puzzle_enter` / `first_valid_action` / `clue_seen` / `hypothesis_preview` / `confirm` / `exit` · `hint_used` · `hint_offer_shown` · `hint_offer_dismissed` · `time_to_first_hint_sec` · `stuck_after_l3` · `undo_count` · `redo_count` · `sandbox_time_min` · `commit_time_min` · `sandbox_discarded` · `checkpoint_created` / `checkpoint_loaded` · `circuit_*` 6종 · `read_count_total` · `auto_copy_created` · `citation_count` · `indeterminate_shown` · `alt_path_offered` · `afk_gap` · `total_min` · **`tool_panel_active_min`** `[C6-F5 신설]` · **`command_count`**.

- **H-10 `manipulation_share` 는 파생값이다** — 빌드는 `tool_panel_active_min`(도구 패널이 열려 있고 입력이 발생한 분)과 `total_min` 을 기록하고, 비율은 보고 시점에 계산한다. 두 원값을 항상 함께 싣는다(비율만 남기면 분모가 사라진다).
- **H-11 은 텔레메트리 키가 아니다.** 사람 답변이며 `qa/t0-playtest-*.md` 의 자유 답변 원문에서만 나온다. 코드가 "재미"를 기록하지 않는다.
- 신설 키는 `systems/ops/telemetry-contract.md` 에 등재돼야 `T-I6` 를 통과한다. 등재 전에는 도구 임포트가 fail-closed 로 막힌다.

**로컬 파일에만 기록한다. 원격 전송 0건. 이름·계정·IP·하드웨어 식별자를 저장하지 않는다.**

### 1.6 보고 형식

- 파일: `_workspace/current/qa/t0-playtest-{YYYYMMDD}.md`(QA 소유) + 원본 `telemetry/*.jsonl` + `afk_review` 원본.
- 표에는 **n · 탈락 수 · 미회고 수**를 항상 함께 적는다.
- **한 사람의 완주 시간은 중앙값이 아니다.** n < 12 이면 "판정 불가"라고 적는다.
- 유도되지 않은 자유 답변 **원문**을 보존한다. 요약만 남기지 않는다.

## 2. 성능 캡처 계획

### 2.1 **기준 하드웨어 미정** — 먼저 적는다

**`hw_profile_id` 는 아직 정해지지 않았다**(`architecture-contract.md` RISK-S1 · `tech-verification/README.md` PRE-1) [OBSERVED].
따라서 이 절의 어떤 수치도 **PASS/FAIL 판정에 쓰이지 않는다.** 캡처는 하되 결론은 미룬다.
`hw_profile_id` 가 빈 결과는 게이트 입력이 아니다(`telemetry-contract.md` §7).

기준기를 정할 때 함께 적어야 하는 것: CPU · GPU · RAM · 저장장치 종류 · OS · 해상도 · 전원 모드. **Windows 우선 대상**이며 macOS 캡처는 **참고값**으로만 표기하고 목표 판정에 쓰지 않는다.

### 2.2 캡처 명령과 산출물

```bash
"$UNITY" -batchmode -projectPath "$PROJ" \
  -executeMethod Tide.Tests.Perf.CaptureCli.Run \
  -captureScenes hub -captureSeconds 120 \
  -out "$OUT/results/frametime-{hw_profile_id}.csv"
```

- **씬은 `hub` 하나다.** `gate` 는 T0 에 없다(첫 등장 C1 `c1-b1`) [OBSERVED].
- 산출: 씬·도구별 `frame_time_ms_p50 / p95 / p99` · `zone_load_ms` · `peak_memory_mb`.
- 함께 잰다: `command_count`/분 (명령 로그 상한 `[INFERENCE]` 를 실측으로 바꾸기 위해 — RISK-S3).

### 2.3 목표값 (전부 `[TARGET]` · 현재 NOT-MEASURED)

| 항목 | 목표 | 축 |
|---|---|---|
| 프레임 시간 @1920×1080 | 16.7 ms | 렌더 |
| **확정 입력 렌더 응답(ack)** | **1프레임 이내** | 렌더 |

| 명령 `Preview` | ≤ 16 ms | 로직 |
| `Commit` + 체크포인트 | ≤ 200 ms | 로직+I/O |
| 되돌림 1스텝 | ≤ 16 ms | 로직 |
| **저장 디스크 완료** | **200 ms** | I/O |
| 세이브 로드 + 로그 재생 | ≤ 1500 ms | I/O |

## 3. 게이트별 측정 방법 — G4 / G5 / G6 / G7

각 게이트의 현재 값은 `qa/gate-measurements.md#g{n}` 이 소유한다. 아래는 **T0 이후 그 칸을 무엇으로 채우는가**다.
**전투가 없는 게임이므로 승률·TTK·일간 인플레이션 게이트는 이유 있는 N/A** 이며, 대체 검사(퍼즐 도달성·힌트·저장 복구·본편 완결성·DLC 비의존성)로 판정한다.

### 3.1 G4 — 연출 / 몰입

| 무엇을 재는가 | 방법 | 통과 조건(제안) |
|---|---|---|
| 시점 전환이 정보를 잃지 않는가 | **모션 축소 ON/OFF 두 조건**에서 같은 참가자가 같은 비트를 수행. 상태 정보 손실 사건 수 | 손실 **0건** |
| 결정적 상태가 색 단독으로 전달되지 않는가 | 그레이스케일 캡처 + 색약 시뮬레이션 3종에서 상태 구분 가능 여부(관측자 2인 독립 채점) | 구분 불가 **0건** |
| 확정의 무게가 전달되는가 | 회상 4단계의 "기억나는 결정" 자유 답변에 **확정 장면이 등장하는 비율** | 보고만(판정선 없음 · 표본 12로는 판정 불가) |
| 프리비즈 ≠ 게임플레이 | 캡처물 파일명·캡션에 `previz` 유지 여부 | 위반 **0건** |

**소스 문서가 `draft` 인 동안에는 G4 를 PASS 로 올리지 않는다.**

### 3.2 G5 — 에셋 / 이펙트 예산

## 4. 판정 절차와 되돌아가는 길

1. 코드 DoD 충족 → 실행자가 `systems/tech-verification/t0-*.md` 에 자동 테스트 영수증을 남긴다.
2. QA 가 **독립적으로** 같은 명령을 재실행한다(재현되지 않는 영수증은 영수증이 아니다).
3. 사람 검증 12명/5유형 수행 → `qa/t0-playtest-*.md`.
4. 디렉터가 게이트 표를 갱신하고 **본 생산 착수 여부**를 판정한다 — 판정 기준은 계약 「Base production gate」 네 조건이며 이 절이 그것을 재서술하지 않는다(C6-F9). 판정은 `production/decision-log.md` 에 append-only.
5. **H-3 가 1건이라도 나오면** 본 생산으로 넘어가지 않는다 — 설계로 되돌아간다(도구 스펙 · 힌트 · 비트 재배분).
6. **H-1 또는 H-2 미달**이면 튜토리얼 비트(`t0-b1`~`t0-b3`)의 안내 밀도를 재설계한다. 목표선을 낮춰 자동 통과시키지 않는다.
