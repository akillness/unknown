# T0 재리서치 → 구현 브리프 R01

## 결론

T0는 또 하나의 “단서 수집 → 증거판” 게임처럼 보이면 안 된다. 시장의 인접작은 이미 그 흐름을 강하게 약속한다. 이 게임의 차별점은 **고정 관찰점의 작업대에서, 출처가 다른 두 기록을 직접 다뤄 하나의 결론을 성립시키는 감각**이어야 한다.

이번 구현 증분은 새 스토리·에셋·도구를 늘리지 않는다. 기존 T0의 `citation` 완료 술어를 플레이어가 첫 60초 안에 이해하도록 하는 **사건 카드(case thread) UI**를 만든다. 카드는 실제 `PuzzleState`/`Simulation`에서만 파생한 현재 목표·진행도를 보이며, 진행 상태를 바꾸거나 정답을 대리하지 않는다. 서랍·문서 화면 이동은 의도적으로 퍼즐 상태를 바꾸지 않으므로 카드의 영속 단계로 사용하지 않는다.

## T0의 설계 판정

### 1. 플레이어 약속

> **작업대에서 서로 다른 두 기록을 대조해 결손의 양 끝을 인용으로 고정한다.**

이 문장은 기존 `t0-b3`의 완료 조건을 사용자 언어로 번역한 것이다. 사건의 인과·서명 이름·순서 앵커는 T0에서 드러내지 않는다.

### 2. 첫 60초의 비파괴적 루프

| 단계 | 플레이어가 보는 것 | 행동 | 시스템이 보장할 것 |
|---|---|---|---|
| 1. 목적 | “결손 4시간의 양 끝을 두 기록으로 고정” + 0/2 | 기존 T0의 실제 읽기·배치·회로 흐름 | 목표가 정답이나 숨은 사건 인과를 누설하지 않음 |
| 2. 준비 | `t0-b1`/`t0-b2`의 실제 완료 상태에 맞춘 일반 동사 안내 | 기존 T0 상호작용 | 카드가 문서·서랍 이동을 진행으로 기록하지 않음 |
| 3. 검증 | “인용 1건 고정” + 1/2 또는 “근거 쌍 고정됨” + 2/2 | 기존 reader/circuit 흐름 | 단일 인용은 독립성을 주장하지 않으며, 카드는 명령을 발행하지 않음 |
| 4. 확인 | `Simulation.IsComplete(state, "t0-b3")`일 때만 완료 문구 | 기존 완료/가설판 흐름 | 실패·벌점·강제 확정 없음 |

### 3. 이번 구현 범위

**구현한다**
- 허브/관련 화면에 현재 T0 사건 카드(목표·진행 0/2~2/2·다음 행동)를 렌더한다.
- 기존 실제 상태에서만 텍스트를 파생한다: `t0-b1`/`t0-b2` 완료, 인용 0/1/2건, `t0-b3` 독립 근거 쌍 완료. 단일 인용은 “인용 1건 고정”으로만 표현한다.
- 기존 마우스·키보드·패드 탐색/확정 입력을 가로채지 않는 읽기 전용 UI로 만든다.
- 집중 PlayMode RED→GREEN, 전체 EditMode/PlayMode, BuildMac, 네이티브 스모크로 검증한다.

**하지 않는다**
- 신규 에셋/생성 리소스, 새 퍼즐 규칙, 승인·`runtimeEligible` 변경, 스토리 공개 상한 변경.
- 자동 인용, 자동 진행, 점수/타이머/벌점, 사람 플레이테스트·성능 주장.
- 기존 미커밋 파일의 범위 확장, 커밋 또는 푸시.

## 성공 조건

1. 새 세이브에서 사건 카드가 T0 목표와 `0/2`를 표시한다.
2. 하나의 유효 인용 뒤 `1/2`, `Simulation.IsComplete(state, "t0-b3")`인 독립 근거 쌍이 생긴 뒤에만 `2/2` 및 완료 상태가 표시된다.
3. 카드 표시만으로 퍼즐 상태·저장·Undo/Redo·선택 노드가 바뀌지 않는다.
4. 카드가 떠 있어도 기존 포인터 클릭, 키보드 탐색, 패드 입력 및 renderer-only 가림 방어가 유지된다.
5. 한국어 전용 T0 범위와 T0 공개 상한을 보존한다.

## 후속 검증 질문 — 아직 미측정

- 12명/5유형 사람 검증에서 첫 조작 중앙값이 60초 이하인가?
- 목표 설명 H-2가 10/12 이상인가?
- 사건 카드가 힌트의 1단과 중복·과잉 안내가 되지 않는가?
- 텍스트 크기·대비·입력 디바이스별 실제 접근성이 충분한가?

이 문서는 위 질문을 통과했다고 주장하지 않는다.
