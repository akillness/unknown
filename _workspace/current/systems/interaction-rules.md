# 상호작용 규칙 — C5 (도구 6종 · 확정 조건 · 힌트 · 복구)

전부 `[TARGET]` 설계다. 플레이·성능 실측 0건. 정의 대상은 **입력 → 보이는 반응 → 확정 조건**의 계약이며, 연출 품질이나 재미의 증거가 아니다. C4 독립 검토(`qa/c4-review.md`) F1·F2·F3 대응은 각 절에 `R1`·`R2`·`R3`로 표시한다.

## 0. 전역 불변식
1. **전역 실시간 타이머 없음.** 진행은 장 완료 위상으로만 옮긴다. 읽는 속도로 벌하지 않는다.
2. **연습·되돌림 무제한, 무료.** 실패는 자원·진행·접근 권한을 빼앗지 않는다.
3. **필수 단서는 첫 판독 시 자동 보존**(`autoKeptClueIds`)되며 어떤 행동으로도 사라지지 않는다.
4. **확정 전 항상 프리뷰**, 확정 성공 시 항상 체크포인트.
5. **재산 보호는 이진 플래그 1개**(`propertyProtection`). 후일담 텍스트 2쌍만 바꾸고 필수 단서·엔딩 3종 접근성은 불변.
6. **세 엔딩은 한 회차 안에서 재시작 없이 도달 가능**하다.
7. 색·소리·움직임 단독으로 결정적 상태를 전달하지 않는다. 항상 문자 라벨이 함께 있다.
8. `R1` **모든 도구 조작은 키보드 단독으로 완결 가능**하다. 포인터·홀드·다중선택은 편의 경로일 뿐 유일 경로가 아니다.
9. `R1` **길게 누름은 선택 기능이다.** 기본값은 2단계 확정이며, 홀드는 옵션에서만 켠다.
10. `R2` **확정은 저장이 성공해야 확정이다.** 저장 전 화면은 후보(candidate)이며 권위 있는 상태가 아니다.
11. `R1` `[C4-F5]` **한 입력 = 한 명령.** 같은 화면에서 하나의 물리 입력이 두 개의 명령을 발행하는 상태는 장치를 가리지 않고 없다. 겸용이 필요하면 (a) **모드 분리**(패널 개폐 같은 배타 상태) 또는 (b) **모디파이어 레이어** 중 하나를 이 문서에 명시해야 하며, 명시되지 않은 겸용은 결함이다. 모디파이어 판정은 §1-2의 **누른 순간 고정(press-time latch)** 규칙을 따른다.
    - `[C4-F20 명문화 2026-09-10 R7 종료]` **누름 시간(짧게/길게)은 해소 방식이 아니다.** 해소 방식은 (a)·(b) **둘뿐**이며 「짧게 A · 길게 B」 는 §0-9(홀드는 선택 기능)와도 충돌한다 — 홀드를 끈 플레이어에게는 B 로 가는 경로가 사라지기 때문이다. 지속시간으로 갈리는 바인딩을 새로 만들지 않는다. **홀드가 남는 자리는 §1-1의 `hold` opt-in 하나뿐이며, 그것은 겸용이 아니라 같은 한 명령(확정)의 입력 방식이다.**
    - 이 규칙 적용 후 저장소의 지속시간 분기 바인딩은 **0건**이다 — 재현: `grep -rn "길게" _workspace/current/systems/system-specs/ _workspace/current/systems/interaction-rules.md` 의 결과에 「짧게 … 길게 …」 형태나 「확정 = 길게 N초」 형태가 남아 있으면 결함이다(§9 변경 로그의 R7 행 참조).

## 1. 입력 계약 `R1`
| 행동 | 마우스(편의) | 키보드 단독(항상 성립) | 컨트롤러 |
|---|---|---|---|
| 시점 노드 이동 | 노드 클릭 | `Tab`/`Shift+Tab` 노드 초점 + `Enter` | 좌스틱 + `A` |
| 대상 조사 | 좌클릭 | 초점 이동 후 `Enter` | `A` |
| 도구 열기 | 도구 휠 클릭 | `1`~`6` 직접 지정 | 패널 밖에서 `Y` 휠, **`RB` = 다음 도구 · `LB`+`RB` = 이전 도구** `[C4-F20]` |
| 값 미세 조절 | 드래그·휠 | 방향키 1스텝, `Shift`+방향키 정밀 | 스틱, D-Pad 1스텝, `LT` 정밀 |
| 커넥터 연결 | 드래그 | **2단계 선택**: 출발 커넥터 `Enter` → 도착 커넥터 `Enter` | `A` 두 번 |
| 연결 해제 | 우클릭 | `Delete` | **패널 안에서만 `Y`** |
| 프리뷰 | 프리뷰 버튼 | `Space` | **`X`(언제나 프리뷰)** |
| 확정 | 확정 버튼 클릭 | 확정 버튼으로 초점 이동 후 `Enter` | 초점 이동 후 `A` |
| 되돌림 / 다시 | 버튼 | `Ctrl+Z` / `Ctrl+Y` | **`LB`(모디파이어)+`X`** / **`LB`+`B`** |
| 증거함·가설판·힌트 | 탭 클릭 | `I` · `H` · `F1` | `back`(증거함) · **`LB`+`back`(가설판)** · **`LB`+`RS`(힌트)** — 3기능 3바인딩 |
| 뒤로/취소 | 닫기 버튼 | `Esc` | `B` |

- **`X` 충돌 해소**: **`X` 단독은 언제나 「부작용 없는 실행」 전용**이다 — 셸 표면에서는 확정 프리뷰, 도구 패널 표면에서는 §1-3.2가 그 패널에 등재한 시험·제안·재생 **1개**. 배선 해제는 `X`를 쓰지 않는다. `LB`를 누른 상태의 `X`는 되돌림이며(§1-2), 그때 프리뷰는 발행되지 않는다 — 두 의미가 동시에 서는 순간은 없다.
- **`Y` 모드 분리**: 패널이 닫혀 있으면 `Y`는 도구 휠, 도구 패널이 열려 있으면 `Y`는 **그 패널이 §1-3.2에 등재한 의미 1개**다(`routing` = 연결 해제 · `reader` = 인용 고정 · 나머지 4종 없음). 도구 패널은 동시에 하나만 열리므로 두 의미가 동시에 활성인 상태는 없다.
- `[C4-F5]` **`LB` 모디파이어 전용**: `LB`에는 **단독 기능이 없다.** `LB`를 누르는 것만으로는 어떤 명령도 발행되지 않으며, 도구 순환은 `LB`에서 내려 **`RB`**로 옮겼다(`RB` = 다음 도구 · `LB`+`RB` = 이전 도구 — **모디파이어 레이어**이며 지속시간으로 갈리지 않는다 `[C4-F20 정정 2026-09-10 R7 종료]`. 어느 쪽이든 `1`~`6`·`Y` 휠로 대체 가능). 따라서 패널 밖에서 되돌림을 하려고 `LB`를 눌러도 도구가 먼저 순환하지 않는다.
- `[C4-F5]` **오버레이 3진입점**: `back` · `LB`+`back` · `LB`+`RS`는 각각 "증거함으로 간다 / 가설판으로 간다 / 힌트로 간다" **한 가지 의미만** 갖는다. 오버레이가 닫혀 있으면 열면서 해당 탭으로, 열려 있으면 그 탭으로 이동하며, **도구 패널이 열려 있어도 같은 입력이 같은 일을 한다**(오버레이는 패널 위에 뜬다). 닫기는 `B`(뒤로/취소) 하나뿐이며, 세 입력 중 어느 것도 닫기를 겸하지 않는다. `RS` **단독**은 오버레이에 쓰지 않는다 — 도구 패널 안의 조회 기능이 이미 갖고 있기 때문이다(`system-specs/wiring-trace.md` §1 · `tide-alignment.md` §1).
- **`Shift` 다중선택은 마우스 전용 편의**다. 키보드·패드는 항목을 하나씩 처리하며 결과가 동일하다.
- **입력 릴리스 래치**: 확정 입력은 버튼을 **놓는 순간**에만 발행된다. 화면 전환·모달 개폐 직후에는 이전 눌림이 새 화면의 확정으로 이어지지 않으며, 래치가 풀린 뒤 새로 눌러야 한다.
- 모든 바인딩은 재매핑 가능하고, 마지막 사용 장치에 따라 프롬프트 글리프가 즉시 바뀐다.

## 1-1. 확정 방식 옵션 `R1`
| 값 | 동작 |
|---|---|
| `two-step` (기본) | 프리뷰 → 초점을 확정 버튼으로 옮겨 한 번 누름. 홀드 없음 |
| `hold` (opt-in) | 확정 버튼에서 0.4초 길게 누름. 시간은 0.2~1.5초로 조절 |
| `confirm-dialog` | 확정 시 확인 대화 1회 |
- 이 설정은 **게임 시작 전 타이틀·부팅 화면의 접근성 설정에서 도달 가능**하며 입력 재매핑 대상에 포함된다.
- 어떤 값에서도 진행 가능한 경로가 존재한다. 홀드 유지가 불가능한 플레이어가 막히는 상태를 만들지 않는다.

## 1-2. 컨트롤러 바인딩 무충돌 규칙 `R1` `[C4-F5]`

§0-11을 컨트롤러에 적용한 것이다. F1 수정이 `X`·`Y`만 훑고 `LB`·`back`/`RS`를 남긴 것이 C4 검토 F5이며, 아래 표는 **패드 입력 전건**을 한 줄씩 세운다.

| 입력 | 단독 의미 | 모디파이어(`LB`) 조합 의미 | 겸용 해소 방식 |
|---|---|---|---|
| `A` | 선택·확정 | — | 단일 |
| `B` | 뒤로/취소(오버레이 닫기 포함) | `LB`+`B` = 다시(redo) | 모디파이어 레이어 |
| `X` | 프리뷰(모든 화면) | `LB`+`X` = 되돌림(undo) | 모디파이어 레이어 |
| `Y` | 패널 밖 = 도구 휠 / 패널 안 = 연결 해제 | `LB`+`Y` = 연습 시작(`Fork`, `drainage-routing.md` L33) | 모드 분리(패널 개폐) + 모디파이어 레이어 |
| `LB` | **없음(모디파이어 전용)** | — | 단독 기능 제거 |
| `RB` | **다음 도구**(1개 명령) | `LB`+`RB` = **이전 도구** | 모디파이어 레이어 `[C4-F20 정정]` |
| `back` | 증거함으로 이동 | `LB`+`back` = 가설판으로 이동 | 모디파이어 레이어 |
| `RS` 클릭 | **도구 패널 안**: 그 도구의 조회 패널(배선 안/밖 · 선후 판정). 패널 밖: 없음 | `LB`+`RS` = 힌트로 이동 | 모디파이어 레이어 + 표면 스코프 |
| `LT` | 값 미세 조절 정밀 | — | 단일 |
| 좌스틱 · D-Pad | 초점 이동 · 값 1스텝 | — | 단일 |

- **누른 순간 고정(press-time latch)**: 모디파이어 판정은 **주 버튼을 누른 순간의 `LB` 상태로 고정**한다. `X`를 누를 때 `LB`가 눌려 있었으면 그 입력은 끝까지 되돌림이며, 도중에 `LB`를 떼도 프리뷰로 바뀌지 않는다. 반대로 `X`를 먼저 누른 뒤 `LB`를 눌러도 그 입력은 프리뷰다. **한 번의 누름이 두 명령을 내는 경로가 없다.**
- 이 규칙은 §1의 **입력 릴리스 래치**(확정 입력은 놓는 순간 발행)와 독립이다. 래치는 *언제* 발행하는가를, 본 규칙은 *무엇을* 발행하는가를 정한다.
- **키보드 단독 경로는 이 절의 영향을 받지 않는다.** §0-8에 따라 위 표의 모든 기능은 `Ctrl+Z`/`Ctrl+Y`·`I`·`H`·`F1`·`1`~`6`으로 모디파이어 없이 도달한다. C4-F5가 blocker가 아니었던 이유이자, 이 수정이 키보드 열을 건드리지 않은 이유다.
- 모든 조합은 재매핑 대상이며, 재매핑 UI는 **한 입력에 두 명령이 걸리는 배치를 거부**하고 사유를 문장으로 표시한다(§0-11의 런타임 강제).

## 1-3. 표면 스코프 우선순위와 키보드 파생 규칙 `[C4-F16]` `[C4-F21]`

§0-11("한 입력 = 한 명령")을 **표면(surface)** 축에 적용한 절이다. §1-2가 패드 축(모디파이어)을 닫았고, 이 절은 같은 물리 입력이 *어느 표면에 배달되는가*를 닫는다. 두 결함이 같은 표를 건드리므로 한 편집으로 세운다(QA 승인: `qa/c4-review.md` §V2.3-(3)).

### 1-3.1 표면은 셋이고 동시에 활성인 표면은 하나다

| 표면 | 정의 | 활성 조건 |
|---|---|---|
| `Shell` | 작업대 셸(시점 노드 · 조사 · 확정 버튼) | 도구 패널·오버레이가 모두 닫혀 있을 때 |
| `ToolPanel(i)` | 도구 패널 6종 중 열려 있는 하나 | 도구 패널이 열려 있고 오버레이가 닫혀 있을 때 |
| `Overlay` | 증거함 · 가설판 · 힌트 · 일시정지 · 확인 대화 | 오버레이가 열려 있을 때(패널 위에 뜬다) |

- **배달 우선순위**: `Overlay` > `ToolPanel(i)` > `Shell`. 입력은 **가장 위 표면 하나에만** 배달되며 아래 표면으로 흘러내리지 않는다.
- **도구 패널은 동시에 하나만 열린다.** `ToolPanel(i)`와 `ToolPanel(j)`가 함께 활성인 상태가 없으므로, 같은 키가 도구마다 다른 의미를 갖는 것은 §0-11 위반이 아니다(모드 분리). 두 패널이 함께 열리는 UI를 도입하려면 이 절부터 고쳐야 한다.
- 오버레이 3진입점(`back` · `LB`+`back` · `LB`+`RS` / `I` · `H` · `F1`)은 §1-2대로 **표면과 무관하게 같은 일**을 한다. 이것이 우선순위의 유일한 예외이며, 예외인 이유는 그 세 입력이 *표면을 바꾸는* 입력이기 때문이다.
- **`[C7-F10]` 그 예외는 진짜 예외로 유지한다 — 조회는 `Q`로 옮겼다.** 이전 판은 이 문장 두 문단 아래 §1-3.2 전수표에서 `I`를 `ToolPanel(circuit)`의 근거 유효성 조회로, `H`를 `ToolPanel(alignment)`의 선후 판정 조회로 재배정해 **자기 자신과 모순**이었다(§0-11 "명시되지 않은 겸용은 결함"). 두 해소안 중:
  - (A) 예외 문장에서 `I`·`H`를 빼고 `F1`만 남긴다 → **기각**. 패드는 `back`/`LB`+`back`으로 패널 안에서도 증거함·가설판에 도달하는데 키보드만 도달하지 못하게 된다. §0-8(키보드 단독 완결)의 **비대칭 손실**이며 접근성 후퇴다.
  - (B) **도구 패널 조회에 자기 키를 준다 → 채택.** 패드의 `RS` **단독**(패널 안 조회)이 이미 오버레이 3진입점과 분리돼 있었고(§1-2 `RS` 행), 키보드만 그 짝이 없어서 `I`·`H`를 빌려 쓰고 있었던 것이다. **`Q` = 그 도구 패널이 등재한 조회 1개**로 짝을 만든다.
  - `[C7-F35 정정 2026-09-10 R8]` **채택 근거의 실측 문장을 고친다.** R7 은 여기에 「`Q`는 저장소 전체에서 미사용 토큰이었다 [OBSERVED 2026-09-10: `grep` 결과 0건]」이라고 적었으나 **그 0건은 재현되지 않는다.** 오늘 실측: `grep -rn '`Q`' _workspace/current/` = **30행**, `systems/`+`handoff/` = **22행**(대부분 R7 이 만든 바인딩 문서 자신), `data-schemas/` = **1행**. 그 1행 — `data-schemas/zones.md` L53(`cycle: 20260909-preproduction-c3`, R7 보다 앞선 문서)의 「`Q`/`E` 순회 순서를 결정」 — 이 **선행 점유**였고, 그것은 `Shell` 표면의 시점 노드 이동을 `Q` 에 걸어 바로 아래 §1-3.2 「`Q` @ `Shell` = 발행할 명령 0개」 및 §1 L29 정본(`Tab`/`Shift+Tab` + `Enter`)과 **정면 충돌**했다. R7 의 grep 이 왜 0을 냈는지는 지금 측정할 수 없으므로 추정하지 않는다 — 기록하는 것은 **재현 실패**라는 사실뿐이다.
  - **그래서 채택 근거는 「비어 있어서 안전했다」가 아니라 「충돌 1건을 정본으로 눌러 비웠다」다.** QA 지정 (a) 안대로 `zones.md` L53 을 §1 정본으로 정정했고(`data-schemas/zones.md` §7 변경 로그), 스키마 문서는 *순회 순서*만 소유하고 *키 배정*은 소유하지 않는다는 경계를 그 파일에 명문화했다. 정정 후 실측: `data-schemas/` 안의 `Q`·`E` 는 **배정 0건**이며 남은 것은 이 정본을 가리키는 인용·부정 문장뿐이다 [OBSERVED 2026-09-10 R8].
  - `E` 는 이 정정 전에는 `zones.md` L53 한 곳에 걸려 있었고, 정정 후 **어떤 표면에도 배정이 없다**. 새 조회 키를 만들 필요가 없었던 이유가 이것이다 — (b) 안(제3의 키 신설)은 `Q` 를 이미 4개 스펙·브리프 4곳·`matrix[19]` 에 심어 놓은 상태에서 **같은 정합 작업을 한 번 더 하게 만들 뿐** 얻는 것이 없어 기각했다.
  - `Q`는 `Shell`·`Overlay` 표면에서는 **발행할 명령이 없다**(무시). 한 키 한 의미이므로 §0-11 위반이 아니며, 재매핑 대상이다.

### 1-3.3 `reader`의 `Space` 예외 명문화

`Space`/`X`는 **부작용 없는 실행**에만 배정한다는 것이 §1-3.2의 규칙이다. `plate-readout.md` §1 「재생(판독)」이 유일하게 상태를 만드는 후보였으므로 다음처럼 갈라 적는다.

| 명령 | 입력 | 상태 변화 |
|---|---|---|
| `Read`(사본 재생) | `Space` / `X` | **없음.** 비용 0 · 횟수 제한 0(`plate-readout.md` P-R2 · P-R9) |
| `ReadOriginal`(원본 직접 절차) | **`Space`가 아니다.** §1-1 확정 흐름(`two-step` 기본)을 거친다 | `readCounts[id] += 1`(상한 3, 비차단) |

이 구분이 없으면 `Space` 한 키가 "부작용 없음"과 "카운터 증가"를 동시에 뜻하게 되어 §0-11이 깨진다. `plate-readout.md` §2 상태기계의 `Read` / `ReadOriginal` 두 전이가 이미 서로 다른 이벤트이므로, 이 절은 **새 규칙을 만든 것이 아니라 입력 배정을 그 구분에 맞춘 것**이다.

### 1-3.4 키보드 파생 규칙 D-1 ~ D-7 `[C4-F21]`

`system-specs/*.md` §1 입력표 **41행 중 20행**은 KB/마우스 열에 포인터 조작(드래그 · 클릭 · 휠 · hover · "메뉴 → 슬롯")만 적고 키보드 토큰을 적지 않는다 [OBSERVED 2026-09-10 · `qa/c4-review.md` X15]. §0-8(키보드 단독 완결)은 전역 보장이지만, **행마다 어느 규칙으로 파생되는지**가 스펙에 없으면 그 보장은 이 문서 한 곳에만 사는 주장이다. 아래가 파생 규칙이며, 각 스펙 §1 표 아래의 **「키보드 파생 [C4-F21]」** 블록이 행 단위로 이 id를 인용한다.

| id | 포인터 조작 | 키보드 단독 경로 |
|---|---|---|
| D-1 | 항목 클릭 · 목록 선택 · 카드 선택 | `Tab`/`Shift+Tab`·방향키로 초점 이동 후 `Enter` |
| D-2 | 두 점을 잇는 드래그(연결) | **2단계 선택**: 출발 `Enter` → 도착 `Enter` |
| D-3 | 연속값 드래그·휠(오프셋 · 배율 · 시간 범위) | 방향키 1스텝, `Shift`+방향키 정밀. **스텝 크기는 그 스펙이 명시**(예: 4분 · 1분) |
| D-4 | hover 정보 | 같은 항목에 초점을 두면 같은 정보가 같은 자리에 뜬다 |
| D-5 | "메뉴 → 슬롯" 경로 | `Esc`로 메뉴를 연 뒤 D-1 |

- **D-3의 스텝 크기가 스펙에 적혀 있지 않으면 그 행은 파생 불가로 본다.** 현재 그런 행은 0건이다(각 스펙 「키보드 파생」 블록에서 스텝 크기를 명시했다).

- 이 절은 **문서 규칙**이다. 재매핑 UI가 파생 경로까지 실제로 보장하는지는 `game-ui-contract.json` `verification.matrix` 실행 전까지 미검증이며, 지금 실행 건수는 0이다.

### 2.1 circuit — 배선 추적 (기구: 회로 지도)
- **입력**: 계통 선을 따라 센서 노드 선택(`Tab`+`Enter` 또는 클릭), 범위 비교.
- **반응**: 선택 계통 강조, 센서 범위 밖은 사선 해칭 + "미배선" 라벨. 범위 밖 근거에는 즉시 배지.
- **확정**: 없음(판독 도구). 다른 도구의 확정에서 배선 범위 밖 근거가 자동 무효화되고 사유가 표시된다.

### 2.2 reader — 판독 (기구: 판독기)
- **입력**: 자료를 판독대에 올리고 시간 범위 지정(드래그 또는 방향키), 배율 조절.
- **반응**: 첫 판독 시 "검증 사본 보존됨" 토스트 + 증거함 항목 생성. 분해능 4분 눈금 상시 표시.
- **확정** `[RFC-C7-001 (1) 반영 2026-09-10 R7 종료]`: **판독(`Read`) 자체는 확정이 아니다.** 확정은 **인용 고정(`CiteToBoard`)** 이며, 그때 출처(`sourceType`·`originId`·계통·관측소)가 기록된다. 확정 조건은 그 네 칸이 **모두 채워졌을 때**다(`planning/gdd.md` §4 reader 확정 층 = 정본).
  - 두 문장은 모순이 아니다 — **판독 ≠ 인용 고정**이며 서로 다른 명령이다. 이전 판의 이 줄은 「판독 자체는 확정이 아니다」에서 멈춰 *무엇이 확정인가*를 적지 않았고, 그래서 브리프가 「T0 에서 확정되는 것은 없다」로 읽혀 DoD 6·8 이 검사 대상을 잃었다(**C7-F8**).
  - 인용 고정은 확정이므로 **프리뷰 → 확정 입력(`two-step` 기본) → 사전 체크포인트 → 저장 → 되돌림**을 모두 거친다(§0-4 · §5). **T0 의 유일한 확정 지점이 여기다**(`systems/data/t0/beats.json` `commitCommandBeats = ["t0-b3"]`).
  - `ReadOriginal`(원본 직접 절차)도 상태를 바꾸므로 확정 흐름을 거치며 `Space`/`X` 에 걸지 않는다(§1-3.3).

### 2.3 alignment — 조위정합 (기구: 정합기)
- **입력**: 두 자료의 곡선을 겹치고 공통 피크 3개 지정, 오프셋 조절(D-Pad·방향키 1분 스텝).
- **반응**: 원시 오차 ±40분 → 정합 후 잔차 ±N분 실시간 갱신. 잔차 4분 초과 시 회색 + "잔차 초과" 라벨.
- **확정**: 피크 3개 + **잔차 절댓값 4분 이하**일 때만 기준선 확정 활성화. 재정합 무제한.
- **선후 판정**: 간격이 두 관측소 오차폭 합(8분)보다 클 때만 순서를 확정한다. 20분 간격은 정합 후 확정 가능. 겹치면 `indeterminate`로 남고 진행은 막히지 않는다.

### 2.4 routing — 배수 편성 (기구: 편성기) `R1`
- **입력**: 커넥터 **2단계 선택**(출발 → 도착)으로 배선. 해제는 우클릭 / `Delete` / 패널 내 `Y`.
- **반응**: 통수 방향 화살표와 예상 수위 막대 갱신, 위반 구간은 붉은 점선 + 위반 이름(문자 병기).
- **확정**: 위반 0건 + 부식예산 한도 내 + 프리뷰 확인. 성공 시 구역 상태가 바뀌고 체크포인트가 생긴다.

### 2.5 corrosion — 부식 시험 (기구: 부식 시험대)
- **입력**: 구성안을 가상 시험대에 올려 무제한·무료 시험.
- **반응**: **구성안 총비용 / 전역 상한 9** 게이지, 초과 시 초과분과 원인 부품 목록. 채집·구매 재화 아님. **소모·차감·잔량 없음**(RFC-P3-009) — 같은 구성안은 몇 번을 시험해도 같은 값이다.
- **확정**: 상한 9 이내에서만 `routing`(배수 편성) 확정이 열린다. **도구 이름은 「부식 시험」이고 자원 이름은 「부식예산」이다** — 둘을 같은 문자열로 쓰지 않는다(C4-F9). 확정해도 **아무것도 차감되지 않는다**. 무료 우회관으로 언제나 복구, 영구 도구 상실 없음. 두 보호 선택지(`lowland` 7 · `dock` 8)는 둘 다 상한 안이다.

### 2.6 seal — 이중서명 (기구: 서명대 · 봉인대)
- **입력**: 결론 카드의 근거 슬롯 2개를 채우고 검증자 확인 → 서명.
- **반응**: 슬롯마다 **종류 배지와 출처 배지를 둘 다** 표시. 판정 실패 시 어느 조건이 어긋났는지 문장으로 표기.
- **확정**: §3 독립성 충족 + 배선 범위 안 + 시간 근거 잔차 4분 이하.
- `R3` seal은 **`proofRequired` 결론에만 요구**된다. 일반 판독·경로 프리뷰·조사 진행은 서명을 강제하지 않는다.

## 3. 근거 독립성 `R3`
- 자료는 `sourceType`(염판/일지/대장)과 `originId`(물리 출처 식별자)를 **분리 저장**한다.
- 독립 판정은 한 문장이다: **`sourceType`이 서로 다르고 `originId`도 서로 다를 때만 독립**이다(AND).
- `copiedFrom`은 재귀적으로 **루트 출처까지 해석**한다. 복제 스캔·표면 부식·재촬영본은 루트의 `originId`를 물려받는다. **표시 라벨은 증명이 아니다** — 배지가 달라 보여도 루트가 같으면 거부한다.
- **확정 사본도 예외가 아니다 `[C3-F12 명문화]`**: 접수부에서 도장을 받은 **확정 사본**, 관외 **주민회 보관 사본**, 그 사본의 사본 — 전부 `copiedFrom` 체인을 따라 **루트 `originId`를 물려받으며 원본과 독립이 아니다.** 행정 절차(접수·공증·이관)는 물리 출처를 새로 만들지 않는다. 따라서 다음 쌍은 독립 판정에서 **거부**된다:

| 거부되는 쌍 | 이유 |
|---|---|
| 조위대장 원본 × 접수부 확정 사본 | 사본이 원본의 루트를 물려받음 (같은 루트) |
| 접수부 확정 사본 × 주민회 보관 사본 | 둘 다 같은 원본 파생 (같은 루트) |
| 서로 다른 관측소의 정당한 염판 2점 | 루트는 다르나 `sourceType`이 같음 (매체 중복) |

  실측 계보 [OBSERVED 2026-09-10, `planning/campaign.json`]: 사본 간선은 2개뿐이며 `bureau-copy-index → council-copybook → tide-ledger-bureau`로 **셋 다 루트가 `tide-ledger-bureau`**다. 즉 이 세 자료 중 어느 둘을 골라도 독립 쌍이 되지 못한다.
- **"확정 사본은 새 루트를 갖는다"는 예외를 두지 않는다.** 그 예외를 두면 게임의 증명 규칙이 행정 도장으로 우회 가능해지고, 법6("원본 책임과 제출을 나눈다")이 요구하는 것이 *두 개의 서명*이 아니라 *두 개의 출처*라는 전제가 무너진다. 이 결정은 `worldview-bible.md` §3-bis.3 P1·P2와 대조 승인이 필요하다 → 아래 RFC-S5.
- **의도된 결과**: 서로 다른 관측소의 정당한 염판 2점은 `originId`가 달라도 `sourceType`이 같으므로 **거부된다**. 이것은 인식론이 아니라 **장르 규칙**(매체 다양성 강제)이며 세계관 §2의 "독립 매체 2종" 문구와 일치한다. C4 검토 F3의 (b) 지적 — "정당한 두 번째 염판이 잘못 거부된다" — 는 이 지점에서 **부분적으로 거짓 양성**이다. 다만 F3이 요구한 `originId` 분리 자체는 (a) 방향에서 옳으므로 수용했다.
- 거부 시에는 어느 조건이 어긋났는지(종류 중복인지 출처 중복인지) 문장으로 알리고, 충족 가능한 다른 자료가 존재함을 힌트 1단계가 안내한다.
- 필수 확정마다 두 조건을 모두 만족하는 자료쌍이 최소 1개 존재하고, 그중 1개 경로는 어떤 플레이어 행동으로도 파괴되지 않는다(임포트 검증으로 강제).

### 3.1 독립쌍 존재 보장 — 문서 주장이 아니라 기계 검사 `[C3-F12]`

| 독립쌍(루트 상이 AND 매체 상이)이 존재하는 비트 | **17 / 17** |
| 독립쌍이 없는 비트 | **0건** |
| 검사 대상 파일 sha256·바이트 | **검증기 출력의 `sha256`·`bytes` 필드를 읽는다.** 이 표에 고정 숫자를 적지 않는다(RFC-Q1·RFC-B6) |

> **수치 갱신 고지**: 이전 판은 「15건 · 15/15」였고 R4 실행의 고정 sha·바이트(`92301c0a…` · 121,457 B · 47/47)를 본문에 옮겨 적고 있었다. planner 가 **RFC-N6** 판정으로 `c1-b2`·`c3-b1` 의 `proofRequired` 를 `true` 로 올리면서 **17건**이 됐고 검사 수도 늘었다. **RFC-S5(확정 사본의 루트 승계 예외 = 예외 없음)는 그대로 성립한다** — 예외 분기 없이 17/17 이 PASS 한다는 것이 이 재실행의 결과다. 고정 숫자를 다시 박지 않기 위해 sha·바이트 열은 명령 인용으로 바꿨다.

실제 쌍은 **`--pairs` 출력이 소유한다**(손으로 고르지 않는다). T0 분: `t0-b3` = `t0-b3-c1`(plate, 루트 `plate-standard-hub`) × `t0-b3-c2`(ledger, 루트 `tide-ledger-bureau`) [OBSERVED · `--pairs`]. 그 쌍은 `systems/data/t0/beats.json` 의 `t0-b3` 완료 술어에 그대로 실린다.

**이 검사가 덮지 않는 것**: C-07은 *데이터에 쌍이 존재함*만 확인한다. "그 쌍의 한쪽이 어떤 플레이어 행동으로도 파괴되지 않는다"(불파괴 보장)는 런타임 규칙이며 **아직 미검증**이다 — `data-schemas/beats.md` B-I11 참조. `synopsis/continuity.md` §5의 K1~K10 경로 표는 이 검사의 대상이 아니므로, 그 표가 사본을 두 번째 근거로 세운 항목은 synopsis 레인이 별도로 정정해야 한다.

## 4. 힌트 3단계 (무료·무제한·기록만 남음)
| 단계 | 주는 것 | 주지 않는 것 |
|---|---|---|
| 1 방향 | 지금 결정할 것, 관련 구역·도구 | 어떤 자료인지 |
| 2 절차 | 필요한 매체 종류와 도구 순서 | 정답 값·정답 대상 |
| 3 해답 | 정확한 자료와 조작 값, 성립 이유 | 이후 장의 진실 |
- 순서대로만 열리며 사용 기록은 저장되지만 엔딩·보상·평가에 영향이 없다.

## 5. 확정 → 저장 → 결과 `R2`
1. **프리뷰(후보)**: 바뀌는 것, 되돌림 가능성, 영향 구역, 근거 2종 요약. 이 화면의 값은 **후보이며 권위가 없다**.
2. **확정 입력**: §1-1 방식으로 발행. 즉시 사전 체크포인트를 기록한다.
3. **`SavePending`**: 진행 표시가 뜨고 **중복 확정만 막는다**. 되돌림·설정·힌트·증거함 열람 등 나머지 UI는 계속 응답한다. 전역 입력 잠금은 없다.
4. **성공**: 저장 영수증 도착 후에만 결과 패널·도장 애니·확정 사운드가 재생된다. 체크포인트 라벨(스테이지·조위 위상)이 확정된다.
5. **실패**: 메모리 상태와 디스크 파일을 **둘 다 확정 이전으로 유지**하고, 성공 연출을 재생하지 않으며, `재시도` / `뒤로` 두 선택지를 문장과 함께 제시한다. 조용한 실패·자동 무시 없음.
6. 5장 제로섬 확정만 `propertyProtection`을 세팅하며, 확정 직전 체크포인트에서 선택을 다시 할 수 있다.

## 6. 저장·복구 `R2`
- **파일 분리**: `save.json`(현재 자동 저장) · `checkpoint.pre-commit.json`(확정 직전) · `save.bak`(직전 세대 백업) · 수동 슬롯 3개. 네 갈래가 서로 다른 파일이라 복구 단계가 실제로 존재한다.
- **쓰기 절차**: 임시 파일 기록 → 플랫폼이 지원하면 fsync → **원자적 rename**. 부분 파일이 정본 자리에 오는 경로가 없다.
- **rename 직후·UI 갱신 전 크래시**: 다음 실행에서 정본이 이미 새 세대이므로 **복구 로드로 그 상태를 이어받는다**(중복 적용 금지, 멱등 키 대조).
- **손상 감지 시**: 복구 패널이 `백업으로 열기 / 사전 체크포인트 / 새로 시작`을 제시하고 **손상 파일을 덮어쓰지 않는다**. 미등록 상위 스키마 저장도 거부하고 파일을 그대로 둔다.
- 자동 저장 지점: 장 경계, 구역 이동, 모든 확정 직전.

## 7. 엔딩·크레딧
- 최종 제출 화면에서 관점 3종을 같은 회차에서 전환·재확정 가능. 잠금·재시작 요구 없음.
- 공통 종결 씬 1개 + 관점별 기록 패널 3개(청문 결과, 4구역 최종 상태, 다음 근무, 판 #0 처리).
- 크레딧은 언제든 건너뛰기 가능하며 이후 마지막 체크포인트로 복귀할 수 있다.

## 8. 한계
- 반응 시간·조작감·난이도는 전부 미측정이다. "즉시", "부드럽게"는 목표이지 관측이 아니다.
- 컨트롤러 매핑과 홀드 시간 범위는 제안이며 실제 패드·보조기기 테스트 0건이다. §1-2의 무충돌 표와 `RB` 롱프레스 역순은 **문서상 무모순**일 뿐이며, 실제 패드에서 오발행이 없는지는 `matrix[17]` 실행 전까지 미검증이다 `[C4-F5 잔여]`.
- 도구 6종은 기능 수이며 공용 작업대 셸 1개 + 도구 패널 6종으로 구현한다.
- §3.1의 C-07은 **저작 데이터에 대한 정적 검사**다. 실제 플레이에서 그 쌍에 도달 가능한지는 도달성 탐색이 필요하며 미실행이다.
- **T0에는 circuit·reader만 들어간다**(`unity-implementation.md` §10). alignment·routing·corrosion·seal의 조작감은 T0로 검증되지 않는다.
- §1-3의 표면 우선순위는 **문서상 무모순**을 세운 것이다. 실제 빌드에서 입력이 그 순서대로 배달되는지는 `game-ui-contract.json` `verification.matrix` 실행 전까지 미검증이며 현재 실행 건수는 **0**이다.
- §2 표시명 4건(`배선 추적`·`판독`·`배수 편성`·`부식 시험`)은 아직 용어집에 없다(RFC-S6). 용어집 규칙상 **미등재 명사는 최종 UI 문자열이 아니다** — 로컬라이즈 키는 만들되 값 확정은 등재 후다.
