# 시스템 스펙 — corrosion-budget (도구 `corrosion`, 법5 "소금은 비용으로 보인다")

> **법 호명 정본** [OBSERVED · RFC-P3-014 · RFC-W3]: 6법의 호명 문구는 `worldview/worldview-bible.md` §3 표(= 아카이브 c3 세션 P 원문) 하나뿐이다. 이 스펙은 인용만 하고 다시 쓰지 않는다. 폐기된 C2 호명 문구는 `worldview/consistency-audit.md` 의 **「사용 금지 문구」 절**(그 안의 표 **「폐기된 6법 호명 문구」** — RFC-W3 이 "사용 금지 문구 원장"이라 부르는 절)에 보존돼 있다. **절 번호로 인용하지 않는다** — 감사 문서의 절 번호가 바뀌어도 이 인용은 살아 있어야 한다(RFC-W3, `qa/c3-review.md` §9.3 q-4 의 QA 대안).

전부 `[TARGET]`. **부식은 재화가 아니다.** `economy/resources-and-fairness.md`가 요구한 대로 구매·채집·시간회복이 존재하지 않으며, 현재 선택의 제약을 보여주는 표시·검증 장치다.

> **RFC-P3-009 반영 (C3-F4 · C3-F9)**: 이 절 이하는 디렉터 판정에 따라 **economy/세션 P 모델**로 재작성됐다. 이전 판의 "6계통 한도(14/14/12/9/9/9)"·"도구 확정마다 누적 소모"·"장 경계 리셋"은 **전부 폐기**한다. 폐기 이유는 §0-1에 남긴다.

## 0-1. 폐기된 모델과 폐기 이유 [RFC-P3-009]

| 폐기된 규정 | 어디에 있었나 | 왜 폐기하는가 |
|---|---|---|
| 계통별 한도 6종 (14/14/12/9/9/9) | `balance/balance-sheet.md` §4.1 (구판) | 데이터에 계통별 한도가 **존재하지 않는다** [OBSERVED: `prototype/model.mjs` `LIMITS`에는 `corrosionLimit: 9` 하나뿐]. 문서에만 있는 한도는 튜닝 노브가 아니라 허구다 |
| 도구 확정 1회당 누적 차감 (circuit → `brine_line 1` + `power_bus 1` 등) | 동상 | `circuit` `reader` `alignment` `seal` 확정은 부식을 건드리지 않는다. 차감 대상이 없다 |
| 장 경계 리셋 | 동상 | **소모가 없으므로 리셋이라는 개념이 성립하지 않는다.** 0을 0으로 되돌리는 규칙은 규칙이 아니다 |
| 연습 시 소모 | 구판 문구 | 연습·프리뷰·되돌림 무소모는 전역 불변식이다(`interaction-rules.md` §0.2) |

C3-F9(자원 차감 시점이 두 규정으로 갈린다)는 이 폐기로 해소된다 — **차감 시점이 존재하지 않으므로 "봉인 순간 차감"과 "도구 확정마다 차감"이 충돌할 자리가 없다.** `worldview-bible.md` §3-bis.2의 "봉인 순간에만"은 법2 재생 카운터(`plate-readout` §3)에만 적용되고 부식에는 적용되지 않는다.

## 0. 자기오염 방지 (C2 QA F5 잔여 지적)

> 지적: "R1의 근거인 부식 패턴이 플레이어의 부식 예산과 같은 계통을 쓰는지 불명."

**분리 규칙**: 12년 전 사건의 **역사적 부식 패턴**(`historicalCorrosion`, 읽기 전용 증거)과 오늘 밤 플레이어 조작의 **운영 부식 비용**(`operationalCorrosion`, 제약)은 **서로 다른 필드**이며 서로를 갱신하지 않는다. 플레이어가 아무리 조작해도 R1 증거는 변하지 않는다. 임포트 검증이 두 필드의 교차 참조를 금지한다.

## 1-A. 키보드 파생 `[C4-F21]`

**신설 2026-09-10 R6 (C6/C7).** §1 표에서 KB/마우스 열이 포인터 조작만 적은 행의 키보드 단독 경로다. 규칙 id 는 `systems/interaction-rules.md` §1-3.4(D-1~D-7)를 인용한다. §0-8(키보드 단독 완결)이 전역 보장이고, 이 표는 그 보장이 **행 단위로** 어떻게 성립하는지를 적는다.

| 위 표의 행 | 파생 규칙 | 키보드 단독 경로 |
|---|---|---|
| 구성안 적재 (`routing` 구성 → 시험대) | **D-7** | `4`로 `routing` 패널을 열어 구성안을 초점 선택(`Enter`) → `5`로 부식 시험 패널로 전환하면 그 구성안이 적재된다 |
| 역사 패턴 판독 (`reader` 경유) | **D-7** | `2`로 판독 패널을 열고 해당 자료를 D-1로 선택해 판독한 뒤 `5`로 돌아온다 |
| 부품별 비용 조회 (`↑↓`) | — | 이미 키보드 경로다(포인터 hover 는 편의 · D-4) |
| 가상 시험 실행 (`Space`) | — | 이미 키보드 경로다 |

- 이 도구에는 드래그·휠·연속값 조작이 없다. D-3 대상 행 **0건**.

## 1-1. 예산 수치 [OBSERVED: `prototype/model.mjs` — tunable: economy]

| 항목 | 값 | 출처 |
|---|---|---|
| 전역 상한 `corrosionLimit` | **9** | `prototype/model.mjs:79` [OBSERVED] |
| 선택지 `lowland` 비용 | **7** | `model.mjs:63-65` [OBSERVED] |
| 선택지 `dock` 비용 | **8** | 〃 |
| 선택지 `dock-express` 비용 | **12** | 〃 — 상한 초과, 확정 불가 |
| 계통별 한도 | **없음(`null`)** | 데이터 부재 [OBSERVED] |

**공정성 요건 (이 도구의 유일한 요건)**: `lowland` 7 ≤ 9 이고 `dock` 8 ≤ 9 이므로 **법4의 두 보호 선택이 모두 예산 안에서 열린다.** 예산이 한쪽을 강제하지 않는다. 안전 하한 `corrosionLimit ≥ max(정상 선택지 비용) + 1 = 9` → **경계 충족(여유 0)**. `dock` 비용이 9로 오르면 권장형이 깨지고 10이면 법4가 붕괴하므로, 이 세 숫자 중 하나라도 바꾸려면 economy·systems 공동 RFC가 필요하다.

계통별 분해는 **UI 표시 라벨**(어느 계통이 비용을 먹는지 보여주기)로만 도입할 수 있고, 실제 차단 규칙으로 승격하려면 프로토타입 불변식 `INV3`(`model.mjs:687`)를 일반화한 뒤에만 한다. 그 전까지 계통 표시는 확정 가능성을 바꾸지 않는다(`economy/currency-map.md` §4.1과 동일 문구).

## 2. 상태기계

상태 변수: `candidateConfigId`, `configCost`, `corrosionLimit`, `trialCount`, `overBy`.
**`systemLimits[systemId]`는 상태 변수가 아니다** — 계통별 한도는 존재하지 않는다.

| 현재 | 이벤트 | 다음 | 부작용 |
|---|---|---|---|
| `Idle` | `LoadCandidate` | `Ready` | 구성안 총비용 / 상한 9 게이지 표시 (계통 분해는 라벨) |
| `Ready` | `RunTrial` | `Trialing` | 비용 계산(결정론), `trialCount += 1` |
| `Trialing` | `configCost ≤ 9` | `WithinBudget` | `routing` 확정 게이트 **열림**. **어떤 값도 차감되지 않는다** |
| `Trialing` | `configCost > 9` | `OverBudget` | 초과분 + 원인 부품 목록 표시, 확정 게이트 닫힘 |
| `OverBudget` | 구성 수정 | `Ready` | 손실 0 |
| `OverBudget` | `UseBypass` | `Ready` | **무료 우회관 1회**, 비용 재계산, 영구 상실 없음 |
| `WithinBudget` | 구성 수정 | `Ready` | 게이트 재평가 |
| any | `Close` | `Idle` | 상태 보존 |

`trialCount`는 **비용이 아니라 계측값**이다. 시험 횟수는 어떤 페널티도 만들지 않는다.

**상태기계에 없는 것**: 잔량 변수, 차감 전이, 리셋 전이, 계통별 고갈 상태. 비용은 **구성안의 함수를 매번 새로 계산**하는 값이며 저장된 잔액이 아니다. 따라서 같은 구성안을 100번 시험해도 결과가 같다.

## 3. 규칙

| id | 규칙 |
|---|---|
| C-R1 | 부식 비용은 구성의 **함수**다: `cost = Σ partCost(part) × pathMultiplier(path)`. 결정론이며 난수 없음 |
| C-R2 | 한도는 **전역 단일 `corrosionLimit = 9`** 이며 [tunable: economy]. 계통별 한도는 존재하지 않는다. 코드 리터럴 금지 — 데이터 테이블에서 읽는다 |
| C-R3 | 초과는 **확정 전에 막힌다**. 확정 후 사후 페널티로 처리하지 않는다 |
| C-R4 | 가상 시험은 무제한·무료. 시간·자원·부식을 소모하지 않는다 |
| C-R9 | **부식은 소모되지 않는다.** 확정(`routing` 커밋 포함)도 부식 잔량을 깎지 않는다. 확정이 하는 일은 "이 구성안이 상한 안인가"를 통과시키는 것뿐이다 |
| C-R10 | `circuit` `reader` `alignment` `seal` 확정은 부식과 **무관**하다. 이 네 도구의 확정 경로에 부식 검사·차감이 들어가면 결함이다 |
| C-R11 | 장·구역·시간 경과로 부식이 회복·리셋·악화되지 않는다. **시간축 의존 0** |
| C-R5 | 한도 초과가 **영구 도구 상실이나 계통 영구 고장을 만들지 않는다**(법5의 원문 실패 조건을 시간·경로 비용으로 낮춘 C2 F5 대응) |
| C-R6 | `historicalCorrosion`은 읽기 전용 증거다. `operationalCorrosion`과 같은 필드·같은 집계에 들어가지 않는다 |
| C-R7 | 부식 게이지는 **정보이자 제약**이며 상점·채집·회복이 없다. 관련 UI에 재화 아이콘·잔량 막대·소진 경고를 쓰지 않는다. 표기는 `구성안 비용 N / 상한 9` |
| C-R8 | sandbox에서는 비용이 표시만 되고 커밋되지 않는다 |
