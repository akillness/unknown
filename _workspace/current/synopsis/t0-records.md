### 5.2 곡선 생성 규칙 (결정적 · systems 가 180행을 그대로 산출한다)

`t` = H 기준 분(정수, 4의 배수, −360 ≤ t ≤ 356).

```
tide(t)      = 500 + 460·cos(2π·t / 744)            # 조위고 cm, 744분 = 12h24m (4분 격자 정수배 근사)
pressure(t)  = 120 + 0.05·(tide(t) − 500)           # kPa, 소수 1자리 반올림
salinity(t)  = 28.0 + 0.004·(tide(t) − 500)         # psu, 소수 1자리 반올림
waterLevel(t)= 0.6·tide(t) + 120                    # cm, 정수 반올림
FLAT   = [[-260,-232], [-196,-168], [-156,-128]]    # 평평 3구간, 각 8샘플(28분)
MISSING= [-60, 176]                                 # 결손, 60샘플 = 240분 = 정확히 4시간
```
- **평평 규칙**: `t` 가 `FLAT` 의 한 구간 `[a,b]` 안이면 `pressure(t) := pressure(a)` 로 고정한다(다른 채널은 그대로).
- **결손 규칙**: `t` 가 `MISSING` 안이면 4채널 전부 `null` 이고 `state = "missing"` 이다. 결손의 **원인은 이 레코드에 없다**(상한 B03).
- 검산 [OBSERVED, 위 규칙을 그대로 실행]: 링 180샘플 · 결손 **60샘플 = 240분 = 4시간 정확** · 평평 **8/8/8 샘플** · `tide(0) = 960` · `tide(−372) = 40` → 대조차 **920 cm ≒ 9.2 m**(bible §1 과 일치).
- 재현 명령: 위 5줄을 그대로 옮긴 `node` 스크립트. 값이 아래 표와 다르면 **표가 틀린 것**이다.

## 10. systems 변환 계약 (제안 · systems 판단으로 바뀔 수 있다)

본 문서의 표 → `systems/data/t0/records.json` 매핑 제안. 필드 이름의 최종 소유는 systems 다.

| JSON 필드 | 출처 |
|---|---|
| `recordId` `medium` `originId` `clueIds[]` `visibleAt[]` `zoneId` | §2 표 1 (행 1:1) |
| `lines[]` (`lineId` `kind` `text` `flag`) | §3.1 · §6 (log 매체) |

- `samples[]` 180행은 **저장하지 말고 규칙에서 생성**할 것을 권한다(§5.2). 표와 파일이 어긋나는 두 번째 진실을 만들지 않기 위해서다. 저장을 택하면 생성 스크립트와 해시를 함께 남긴다.
- planner 의 `T0-01~` 검사(인스턴스 ↔ 캠페인 단서 id·`originId`·매체 일치)가 참조할 키는 §2 표 1 의 `clueIds`·`originId`·`medium` 세 열이다.
- `t0-b1`~`b3` 완료 술어(RFC-C7-001 (3))는 **systems 소유**다. 본 문서는 그 술어가 가리킬 대상만 만든다 — `tl-r4` 기입 여부(`t0-b1`), 평평 3구간 표시(`t0-b2`), 결손 양 끝 고정 + 사본 1점(`t0-b3`).

## 11. 이 문서가 증명하지 않는 것 [OBSERVED]

- **실측 0건.** 값이 플레이에서 읽히는지, 읽는 데 몇 분이 걸리는지, 평평 3구간이 눈에 보이는지 — 전부 n=0 이다. `t0-b2` 의 10분·`t0-b3` 의 10분은 설계 배분이다.
- **곡선이 그럴듯하다는 것은 물리 검증이 아니다.** §5.2 의 4식은 캐논 문장(대조차 9.2 m, 4분 분해능)을 만족하는 하나의 표현일 뿐이며 조석·염선 유체의 모형이 아니다.
- **레코드가 있다는 것은 퍼즐이 성립한다는 뜻이 아니다.** 결손 60샘플 ↔ 공백 0칸의 대조가 플레이어에게 "계통이 전부 죽지는 않았다"로 읽히는지는 T0 사람 검증(H-2 목표 설명 10/12)에서만 확인된다 — 계약 「Base production gate」 1.
- **systems 가 이 표를 실제로 변환했는지, Unity 가 그것을 읽는지 미확인**(슬라이스 0줄).

## 12. T0 인용 출처 귀속 — 기계 판독 저작본 (RFC-CX-001 · RFC-CX-003)

**[TARGET · 저작 결정 · synopsis ACK / 교차 레인 ACK·독립 QA 대기]** 이 절은 `production/decision-log.md`의 RFC-CX-003 「RFC-CX-001 director ruling」과 [용어집 §6-2](../worldview/glossary.md#6-2-t0-인용-출처-식별자-rfc-cx-001), `worldview/consistency-audit.md` §7을 적용한다. §1~§11의 레코드 본문·단서·`originId`·카탈로그 신원은 유지한다. 이전 절의 실행·미측정 진술은 그 작성 시점의 기록이며, 이 보충 저작은 생성기 반영·Unity 동작·게이트 통과를 증명하지 않는다.

`system-hub`와 `station-bureau-standard`의 문자열 지정은 이번 기술 저작이다. **당직실 표준판의 `stationId`는 새로 채택한 조위 비교 기준**이며, 기존 문서에서 관측 생산지를 추출한 결과가 아니다. 그 관측소가 판의 압력·염도·갑문 내측 수위를 생산했다는 뜻이 아니며, 새 장소·센서·사건·측정값·오차폭을 만들지 않는다. 기록국 조위대장의 `systemId: null`은 계통 비해당이다(`systems/data-schemas/plates.md` §1: `sourceType == plate`일 때만 계통 필수).

다음 두 마커 사이의 **JSON 배열 한 개**를 systems 생성기의 추가 저작 입력으로 삼는다. 필수 필드는 `recordId`, `systemId`, `stationId`, `assignmentKind`, `evidence`, `decisionRfc`이며, `systemId`의 `null`은 문자열로 바꾸지 않는다. `evidence`는 기존 문서 사실 `[OBSERVED]`와 이번 저작 `[TARGET]`을 구분한 문자열 배열이다. `decisionRfc`는 귀속의 근거 결정 ID 배열이다.
