### 4.3 첫 사건: t0-b1 → t0-b2 → t0-b3

1. **인수 `t0-b1`, hub H0:** 문서·빈 항목·판 #0을 확인한다. 플레이어가 직접 정할 작은 절차가 있지만 이것은 워밍업이다. 판 #0과 표준 염판을 동일 물건처럼 표현하지 않는다.
2. **기록의 범위 `t0-b2`, hub H0:** 회로 투명지의 기준점을 맞추고 회선 밖 구획을 표시한다. “기록되지 않음”을 “아무 일 없음”으로 확정할 수 없음을 행동 결과로 보여준다. 정렬을 성공해도 사건 결론은 아직 없다.
3. **비교 `t0-b3`, hub H0:** 표준 염판과 조위대장의 선택 구간을 나란히 고정한다. 그래프·시간 선택과 동일한 키보드 순차 조절을 제공한다. 염판 결손과 대장의 지속을 보고 시작/끝을 선택한다.
4. **인용:** 각 자료의 시간창을 프리뷰하고 명시적으로 고정한다. 인용 카운터가 채워졌다는 이유만으로 사용자가 의미를 이해했다고 판단하지 않는다.
5. **보상:** 이미 확보한 범위 안에서 “정전이라면 왜 대장 수치는 살아 있는가?”라는 열린 질문을 남긴다. 범인·어머니의 이름·의도를 말하지 않는다. C1 전환은 그 질문에 필요한 조사로 설명한다.

**[TARGET] 정식 첫 슬라이스는 기존 T0 세 비트를 중심으로 동결한다.** 정본 T0는 설계 목표 25분이며 이를 유지한 채 실측한다. T0 25분에 C1 11+13분을 더해 놓고 ‘20~30분 슬라이스’라 부르지 않는다. C1 `c1-b1`/`c1-b2`는 별도 후속 관찰 또는 앞부분을 생략한 명시적 continuation 조건으로 다룬다. 후자는 초회 T0 H-1/H-2 표본에 섞지 않는다.

- 도입 → 회로 범위 → 판독·대조 → 인용 → 새 질문이 한 회차 안에서 닫히는지 확인한다.
- 빨리 끝났다는 이유로 반복 판독·왕복 걷기·필수 메모 분량을 추가하지 않는다.

- 재진입은 진행·보존 자료·마지막 확정·미해결 질문을 보여주되 답을 채우지 않는다. 다시 켜서 무엇을 해야 할지 묻는 평가는 별도 후속 측정이며 초회 완료 시간에 로딩을 합산하지 않는다.

### 8.5 실제 Deep Research / Ultra Browser 실행 경로와 한계

**[OBSERVED] 사용한 스킬:** 계정의 `deep-research/SKILL.md`, `references/deep-pipeline.md`, `references/web-search-pipeline.md`의 `general-web`, `references/report-pipeline.md`를 실제로 읽었다. `aside/SKILL.md`도 읽고 현재 세션 정보만 조회했다.

**실제 연구 절차:**

1. 지정 handoff를 첫 번째 도구 호출로 읽고 A/B/C와 8개 결과 절을 연구 목차로 고정했다. 기존 계약이 목차·출처 우선순위·언어·출력 위치를 정했으므로 새 범위 인터뷰는 하지 않았다.
2. 파일 기반 game-planner·systems·balance·QA 정의를 읽은 뒤 저장소 조사를 두 읽기 전용 조사자에게 나눴다. 웹은 Obra Dinn/Papers, Please, Room/Myst/Outer Wilds, Roottrees/접근성의 세 독립 묶음으로 조사했다. 부모는 Golden Idol 개발자 인터뷰와 현재 코드·M22 이미지·상충 주장 재검증을 맡았다.
3. `functions.websearch`의 advanced 검색과 `functions.webfetch` 본문 읽기를 사용했다. 각 웹 결과는 제목·URL·시점·본문 읽기 여부·좁은 주장·적용/비적용·불확실성으로 받았다. 서브에이전트의 수치·단정은 무조건 채택하지 않았다. 특히 초기 문서에서 나온 ‘빌드 0’은 M22로 반증했고, ‘현재 항구 변화’와 ‘과거 사실 변화’를 구별했다.
4. **실제 Aside 브라우저 경로:** `functions.repl → openTab → snapshot(page, {interactive:true})`로 Golden Idol 인터뷰, Microsoft XAG 115, Lucas Pope의 휴대폰 이식 원문을 열었다. 읽기 전용 탐색이었고 계정 로그인·양식 제출·자동 요약 버튼을 사용하지 않았다. Google/Gmail·브라우징 이력·인증값·다른 프로젝트는 읽지 않았다.
5. 현재 세션 `45OZ1GSC9FAud0zE`는 `aside.sessions.current/get`에서 `trigger.source=cli`로 확인됐다. **`--effort ultrabrowse`로 시작했다는 사실은 사용자 제공 시작 문맥**이다. 조회 API에는 effort/runtimeConfig가 노출되지 않아 해당 문자열을 독립 검증하지 못했다. 별도의 ‘Ultra Browser’ 전용 도구나 독립 Deep Research SaaS 작업을 호출했다고 주장하지 않는다.
6. 명시적 `deep` 모델을 지정한 웹 조사 두 건은 `402 Insufficient credits`로 실패했고, 한 건의 재시도도 같은 오류였다. 성공한 조사로 세지 않았다. 사용 가능한 기본 프로필로 두 웹 작업을 다시 배정해 자료를 확보했다. 결제·계정·모델 설정 변경은 하지 않았다.
7. **스킬의 표준 파일 파이프라인과 다른 점:** 사용자 계약이 출력 한 파일·스크립트/테스트 금지를 우선하므로 `outline.yaml`, `fields.yaml`, per-item JSON, `validate_json.py`, `generate_report.py`를 만들거나 실행하지 않았다. 따라서 **표준 Deep Research JSON 검증 PASS라고 주장하지 않는다.** 실제 사용은 스킬의 병렬 원문 조사·필드별 증거·불확실성 분리·통합 보고 절차를 이 계약에 맞게 수행한 것이다.
8. 읽기는 `read_file`, 읽기 전용 `rg/stat`, 선택 JSON 필드의 `node -e` 조회를 사용했다. REPL `fs`는 프로젝트 밖 경로 제한으로 대상 파일 상태를 확인하지 못했으나 `read_file`/허용된 읽기 명령으로 저장소 접근은 가능했다. 이를 파일 존재나 프로젝트 미접근으로 잘못 판정하지 않았다. 검증기·시작 동기화 스크립트는 재실행하지 않았다. 시작 동기화는 Main이 이미 수행했다는 handoff를 따랐다.

**최종 문서 검수:** 부모 Aside가 인물 배치 2곳을 JSON 정본에 맞춰 고쳤고, 조사 중 추가된 M22 초점 복원 영수증을 반영했다. 별도 읽기 전용 검수자가 handoff와 game-qa 역할을 기준으로 8개 결과 절·권고 10개·실험 3개·12명/5유형·고유 157건·목표/실측 구분·승인 경계를 대조해 중대한 오류 없음으로 보고했다. 그 검수자는 외부 웹 인용을 재검증하지 않았으며, 웹 근거는 위 원문 조사 범위다.

**보고서 검수 경계:** 문서 검수는 제품 QA 게이트 승인이 아니다. 이 보고서의 수용선은 계획과 기존 계약 인용으로 분리했고, 현재 M22 증거와 옛 문서의 미실행 상태를 분리했다. 새 RFC 합의·사람 플레이·독립 QA 승인·runtimeApproved 변경은 없다. 후속 Main은 이 문서의 P0를 검토하고 소유 레인에 변경 범위를 배정해야 한다.
