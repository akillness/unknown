# recap-panel · 세션 재개 요약 (C6-F4)

```yaml
feature_id: recap-panel
name_ko: 재개 요약
name_en: Recap Panel
opened_by: C6-F4            # qa/c6-review.md — "재개|이어하기|리캡|recap|resume" 0건
assigned_by: game-production-director   # decision-log.md 「C6/C7 디렉터 판정 묶음」 R7 레인 배정 표
layer: overlay              # 게임플레이 층이 아니다. 확정도 되돌림도 하지 않는다
trigger: 세이브 로드 직후 1회 (자동) + 오버레이에서 언제든 다시 열기
goal: >
  480분 설계 분량을 주말 2~4회로 나눠 플레이하는 이용자가, 하루 뒤에 돌아와도
  "무엇이 확정됐고 무엇이 열려 있으며 지금 무엇을 해야 하는가"를 맨손으로
  다시 읽지 않게 한다. 단서 73건과 33비트 사건판을 기억 과제로 만들지 않는다.
player_fantasy: >
  당직을 교대하고 돌아온 사람이 인계 노트 한 장을 집어 드는 순간 — 어젯밤 내가
  무엇까지 적어 두었는지가 한눈에 잡히고, 손이 바로 다음 자리로 간다.
touched_lanes: [systems, presentation, qa]
blocked_on: RFC-P4-001      # 인용 고정의 저장 필드 부재 (아래 §deps)

> **왜 이 스펙이 필요한가** [OBSERVED, `qa/c6-review.md` C6-F4]: `gdd.md` · `systems/interaction-rules.md` · `systems/data-schemas/save.md` 세 문서에 「재개 / 이어하기 / 리캡 / recap / resume」 검색 결과가 **0건**이었다. `gdd.md` §7의 슬롯 카드는 **장 · 조위 위상 · 플레이 시간** 셋만 표시한다 — 그것은 "어느 세이브인가"를 고르게 해 주지, "무엇을 하던 중이었나"를 말해 주지 않는다.
> **이 스펙이 만들지 않는 것**: 새 진행 상태, 새 확정 명령, 새 자원. 재개 요약은 **이미 세이브에 있는 값의 표시**이며 그 값을 바꾸지 않는다.

## rules

| # | 규칙 | 근거 |
|---|---|---|
| R1 | 재개 요약은 **네 블록**을 이 순서로 보여 준다 — ① 마지막 체크포인트 ② 현재 스테이지의 목표 ③ 열린 가설·남은 질문 ④ 최근 인용 고정 | C6-F4 디렉터 배정 문구 |
| R2 | ① **마지막 체크포인트**: `progress.checkpoints[]`의 마지막 항목(라벨 = 장 · 조위 위상 · 플레이 시간)과 `beatId`를 그대로 표시한다. 새 라벨을 만들지 않는다 | `systems/data-schemas/save.md` §1·§2 |
| R3 | ② **현재 스테이지 목표**: `stageId`·`beatId`로 live `campaign.json`의 그 비트 `objective` **한 문장**을 읽어 표시한다. 문장을 요약·재작성하지 않는다(데이터가 정본) | `planning/campaign.json` `beats[].objective` |
| R4 | ③ **열린 가설**: 사건판에 열려 있는 항목 — 그 비트의 `completion`이 아직 충족되지 않은 조건, 그리고 이전 비트가 남긴 "남는 질문"(예: `t0-b3`의 "정전이라면 왜 대장 수치는 살아 있는가") | `campaign.json` `completion`·`inference` |
| R5 | ④ **최근 인용 고정**: `reader` 확정(인용 고정)으로 가설판에 남은 최근 **3건**을 `매체 · 계통 · 관측소` 출처와 함께 표시한다. T0의 확정 명령이 바로 이것이다 | RFC-C7-001 (1) · `gdd.md` §4 `reader` 행 |
| R6 | 재개 요약은 **읽기 전용**이다 — 이 패널에서 확정·되돌림·삭제·인용 해제를 할 수 없다. 각 블록은 해당 화면(사건판 · 증거함 · 가설판)으로 **이동만** 시킨다 | `gdd.md` §3.3 원칙 4(연습·표시는 상태를 바꾸지 않는다) |
| R7 | 표시는 **저장된 값만** 쓴다. 파생 계산이 필요한 항목(부식 비용 등)은 이 패널에 넣지 않는다 | `save.md` §2.1 |
| R8 | 로드 직후 자동으로 **1회** 뜨고, `B`(뒤로/취소) 한 번으로 닫힌다. 자동 표시는 설정에서 끌 수 있으며 끈 뒤에도 오버레이에서 언제든 열 수 있다 | `systems/interaction-rules.md` §1-3.1(오버레이 닫기는 `B` 하나) |
| R9 | 입력은 **기존 오버레이 계약 안에서** 배정한다. 새 전역 키를 요구하지 않는다 — 배정 자체는 systems 소유이며 본 스펙은 "새 키를 요구하지 않는다"만 계약한다 | `systems/interaction-rules.md` §1-2·§1-3.2 |
| R10 | 텍스트는 **전부 KO**다. EN 문자열은 로컬라이제이션 회차 산출물이다(T0 KO 전용) | RFC-S6 / C7-F5 |
| R11 | 접근성: 네 블록은 **스크린리더 읽기 순서 = 표시 순서**이고, 색 단독으로 구분하지 않으며(문자 라벨 병기), 텍스트 3단 확대에서 잘림 0건이어야 한다 | `gdd.md` §8 |

## edge_cases

| # | 상황 | 요구 동작 |
|---|---|---|
| E1 | 새 게임 첫 실행(체크포인트 0건) | 패널을 띄우지 않는다. "재개할 것이 없다"는 문구도 띄우지 않는다 |
| E2 | `t0-b1` 진행 중(도구 0개, 인용 고정 0건) | ④ 블록을 **비우지 않고 숨긴다**(빈 카드 금지). ①②③만 표시 |
| E3 | 손상 세이브를 복구 패널로 열었다 | 복구 패널이 먼저다. 재개 요약은 복구가 끝난 뒤에 뜨고, 복구로 잃은 구간이 있으면 ①의 체크포인트 라벨이 그 사실을 그대로 보여 준다(손상 파일 덮어쓰기 금지) |
| E4 | 되돌림으로 인용 고정이 취소된 뒤 재개 | ④는 **현재 세이브 상태**를 보여 준다. 취소된 인용은 나오지 않는다(패널이 별도 이력을 갖지 않는다) |
| E5 | 확정 진행 중 크래시 후 재개(`commitIdempotencyKey ≠ null`) | 재개 요약보다 확정 트랜잭션 복구가 먼저다. 복구 결과가 반영된 상태로 패널을 그린다 |
| E6 | 같은 세이브를 이어서 여러 번 로드(하루에 3회) | 매 로드마다 뜬다. "이미 봤음" 상태를 세이브에 기록하지 않는다(세이브 필드 추가 금지) |
| E7 | 스테이지 경계 직후(직전 스테이지 목표는 끝났고 새 목표가 시작) | ②는 **현재 `beatId`의 목표**를 쓴다. 직전 스테이지 요약을 함께 띄우지 않는다 |
| E8 | 텍스트가 길어 4블록이 한 화면을 넘는다 | ③·④를 각각 **최대 3항목**으로 자르고 "더 보기"는 해당 화면으로 이동시킨다(패널 안에서 스크롤 금지) |

## acceptance_criteria

### A — 문서·데이터로 지금 검사 가능 (numeric)

| id | 기준 | 측정 방법 | 현재 |
|---|---|---|---|
| A1 | 네 블록의 **원천 필드가 전건 존재**한다 — 파생 불가 항목 **0건** | `save.md` §1·§2 필드 대조 | **미충족 1건** — ①②③은 `checkpoints`·`stageId`·`beatId` + `campaign.json`으로 성립하나 ④ **인용 고정에는 저장 필드가 없다**(§deps) |
| A2 | ②의 목표 문장이 live 데이터에서 **33/33 비트** 존재 | `node -e` 로 `beats[].objective` 빈 값 검사 → **0건 빈 값** [OBSERVED 2026-09-10] | **PASS** |
| A3 | ③의 "남는 질문" 원천이 되는 `completion` 문장이 **33/33** 존재 | 동상 (`completion` 빈 값 0건) | **PASS** |
| A4 | 패널 표시까지 필요한 플레이어 입력 **0회**(자동), 닫기 **1회** | UI 계약 검수(`game-ui-contract.json`) | systems 확인 필요 |
| A5 | 새로 요구하는 **전역 키 0개 · 새 세이브 필드 0개** | `interaction-rules.md` §1-2 표 · `save.md` §1·§2 대조 | **PASS(설계상)** — ④의 필드는 이 스펙이 새로 요구하는 것이 아니라 RFC-C7-001이 이미 요구하는 것이다 |
| A6 | 블록당 표시 항목 **≤ 3**, 패널 내부 스크롤 **0** | 레이아웃 검수 | presentation 확인 필요 |

### B — 빌드 후에만 측정 가능 (표본 n = 0)

| id | 기준 | 표본 |
|---|---|---|
| B1 | **20시간 이상** 중단 후 재개한 참가자가 "지금 무엇을 해야 하는가"를 **60초 이내**에 말한다 — **10 / 12** | 12명 / 5유형(T0 검증 프로토콜과 같은 표본 규약) |
| B2 | 재개 후 **첫 유의미 조작**까지 중앙값 **≤ 90초** | 동일 |
| B3 | 재개 직후 열린 가설을 **잘못 기억한 채** 진행한 사례 **0건** | 동일 |
| B4 | 패널을 **읽지 않고 닫은 비율** | 목표값 없음 — **관측만 한다**. 이 값이 높으면 패널이 아니라 배치·시점을 다시 본다 |

> **정직성** [OBSERVED]: A는 문서·데이터 정합이고 B는 사람 표본이다. **A 전건 PASS는 재개 요약이 실제로 기억 부담을 덜어 준다는 증거가 아니다.** 현재 표본은 n = 0이며 B1~B4 중 어느 것도 측정되지 않았다.
