### 1.1 비트 순서의 정본도 live JSON이다 [OBSERVED]

live JSON의 배열 순서와 `synopsis/chapter-beats.md`의 B 번호 순서가 **C1·C3·C4·C5·C7에서 다르다**(예: C1은 JSON `c1-b1→c1-b2→c1-b3→c1-b4`, 표 A는 `c1-b3 → c1-b1 → c1-b2 → c1-b4`).

**B# 표기 주의 (C3-F30)** [OBSERVED]: 위 문장의 순서 차이는 **재생 순서**의 차이이며 B# 번호의 차이가 아니다. B#의 정의는 하나뿐이다 — 디렉터 판정에 따라 **스테이지 순서대로 `t0-b1`=B01 … `e0-b2`=B33**이며 본 문서 표 1·표 2는 그 정의로 재도출했다(R4). 표 A가 아직 옛 부여를 쓰므로 **문서 간 인용은 B#가 아니라 `사건 id`로 한다**.
재방문 런(D2)·신규 자산 비율은 **순서에 의존**하므로 본 문서는 **JSON 배열 순서**를 재생 순서로 삼는다(RFC-P3-008의 귀결). 그래서 §6의 구역별 런 분포가 `content-matrix.md` 이전 판의 값과 다르다 — 합계 16은 같고 분포가 다르다. 순서 자체의 정본화는 synopsis와의 확인이 필요하다 → §11.

## 2. 행동 5범주와 배분 규칙 [TARGET]

**이 절의 지위 (2026-09-10 변경)** [OBSERVED]: 5범주 분해의 **정본은 이제 데이터**다 — live `campaign.json`의 비트별 `activityBudget`(표 1). 아래 U1~U10 가중 모델은 그 데이터를 **독립적으로 재계산해 보는 교차 점검**으로만 남긴다(§4.2). 두 계산은 서로를 검증하지 않는다 — 둘 다 저자 가정이고 실측이 아니다.

### 2.1 범주 정의

| 범주 | 포함 | 불포함 |
|---|---|---|
| 탐색 | 매체를 찾아 펼치기, 해당 구간 훑기, 신규 구역·상태의 최초 관찰 | 걷기, 배회, 자동 이동 |
| 추론 | 매체쌍 대조, 가설 세우기·배제, 판정 문장 고르기 | 도구 조작 자체 |
| 조작 | 도구 확정 1회(슬롯 구성 → 조작 → 확정), 서로 다른 구성의 연습 시행 1회 | 같은 구성 반복, 되돌림 |
| 대화 | NPC 교환 블록(씬 재생 + 응답 선택) | 대화 중 판정(→ 추론) |
| 결과 | 확정 프리뷰·손실 목록 열람, 상태 변화 확인, 장 정산 열람 | 크레딧, 후일담 선택 콘텐츠 |

### 2.3 배분식

```
raw(범주) = Σ 해당 단위 가중 × 그 비트의 단위 횟수
배정(범주) = 비트 분 × raw(범주) / Σ raw   → 최대잔여법으로 정수화
```

[OBSERVED] 결과적으로 **각 비트의 5범주 합 = 그 비트의 분**이며(33/33 일치, 표 1 `합검산` 열), 어떤 분도 두 범주에 동시에 계상되지 않는다. 입력은 (매체 수, 신규 상태 여부, 확정 수, 고유 연습 시행 수, 비트 종류) 다섯 개뿐이라 제3자가 같은 표를 재생성할 수 있다.

[INFERENCE] 가중치 자체에는 관측 근거가 없다. 실측 후 U1~U10을 조정하면 배분은 바뀌고 **총합 480은 바뀌지 않는다** — 총합은 비트 분에서 오고 가중치는 그 안의 분배만 정한다.

| 미달 시 결정 규칙 사전 명시 | 해소 | RFC-P3-011 (a) 콘텐츠 증설 / (b) 8시간 주장 철회. **목표를 낮춰 자동 통과시키지 않는다** |

**선언**: C1-F4는 **정의·규칙 수준에서 해소**됐고 **판정 수준에서는 미해소**다. 본 문서는 `design_budget_min`만 만들며 `observed_*`를 하나도 만들지 않는다.

### 9.3 시간 수용 판정 — **RFC-P3-011 문구로 통일** [OBSERVED]

이전 판은 `design_fast_min`(당시 321)이 하한 360을 밑도는 것을 "별도 위험으로 유지"한다고 적었고, `campaign.meta.md` §6-1은 같은 비교를 "범주 오류"로 기각했다. 두 문장이 동시에 `_workspace/current`에 살아 있었다(C3-F14). 디렉터가 닫았다.

| 항목 | 확정된 문구 |
|---|---|
| **판정 키** | **`total_minus_afk_min`** 하나. AFK 구간은 회고로 판별하며 **60초 무입력을 자동 제외하지 않는다** |
| 병기 | `total_min` · `afk_total_min` 필수. 제외 여부를 밝히지 않은 시간 수치는 무효(`telemetry-contract.md` §5 AF4) |
| **목표 밴드** | 처음 플레이하는 일반 이용자(공략 없음) 완주 **중앙값 450~540분** |
| **철회 트리거** | 중앙값 **< 420** 또는 **하위 25% < 360** → "8시간" 주장 철회 또는 콘텐츠 증설. **통과선이 아니다.** 목표를 낮춰 자동 통과시키지 않는다 |
| **p75 조건** | **삭제.** `deliberateMinutes` 합 673을 상한 600과 비교하지 않는다 |
| `fastMinutes` 322 / `deliberateMinutes` 673 | **시나리오 경계**이며 표본 통계와 비교하지 않는다(범주 오류 지적 채택) |
| 표본 | 최소 12명 / 5유형, 탈락 포함 보고 |
| 합산 제외 | 선택 콘텐츠 · NG+ · 수집 100% · 로딩 · 일시정지 · 자리비움 · 재시작 대기 |

[OBSERVED] 따라서 "**321 < 360이므로 위험**"이라는 이전 판의 문장은 **철회한다** — 322는 시나리오 경계이지 표본 하위 25%가 아니며, 두 값은 같은 축에 놓이지 않는다.
[INFERENCE] 그러나 그 문장이 가리키던 **설계 위험 자체는 남는다**: 빠르게 진행하는 플레이어의 시나리오 경계가 목표 밴드(450~540) 아래에 있다는 사실은, 실제 하위 25%가 철회 트리거(360)에 닿을 가능성을 배제하지 못한다. 이것은 **측정으로만 판정된다**(§10). 위험으로 유지하되 **수치 비교로 주장하지 않는다.**

## 12. 이 문서가 증명하지 않는 것 [OBSERVED]

- 480분을 **플레이한 사람이 0명**이다. 이 문서는 배분을 증명할 뿐 소요를 증명하지 않는다.
- 5범주 분해(`activityBudget` 53/190/168/28/41)와 U1~U10 가중치는 둘 다 관측이 아니라 저자 가정이다. §4.2의 순위 일치는 서로를 검증하지 않는다.
- 신규 자산 **28.9%**는 에셋 산정이 아니라 일정 가정이다. R4에서 값이 30.0 → 28.9로 움직인 이유는 콘텐츠 변화가 아니라 **구역 배정 출처가 바뀐 것**뿐이다(§5).
- 본 문서는 어떤 게이트도 PASS시키지 않는다. G7(피처 수용·코어루프)은 빌드와 플레이 없이는 `[NOT-MEASURED]`다.
