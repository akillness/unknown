# Motion and Focus

전부 `[TARGET]` 설계다. **실측 0건**(n=0): 입력 지연·프레임 타임·저장 완료 시간 어느 것도 캡처하지 않았고, 아래 ms 값은 캡처 도구가 붙기 전의 설계 목표다. 정본 대조 기준은 `systems/interaction-rules.md` §0-9·§0-10·§1-1·§5·§6 과 `animation/animation-contract.md`(전역 입력 잠금 없음 · 도장은 영수증 이후)이며, 두 문서와 이 문서가 어긋나면 저쪽이 정본이다.

## 1. 전환 타이밍 `[TARGET]`
| 대상 | 목표 | 비고 |
|---|---|---|
| 노드 카메라 이동 | 650ms | 최대 2앵커 |
| 작업대 확대 | 220ms | |
| 기록 서랍 | 180ms | |
| hint 펼침 | 140ms | 힌트는 무료·무제한(§4)이라 지연 페널티를 두지 않는다 |
| 확정 결과 패널 | 180ms | **시작점은 저장 영수증 도착 시각**(§2). 확정 입력 → 패널 완료의 총 시간이 180ms 라는 뜻이 아니다 |
| 장 전환 | 600ms | |
| 오류 shake | 0 | 실패는 흔들림이 아니라 문장으로 알린다(§0-7 · §5-5) |
- 저감모션: 카메라 hardcut + 120ms dissolve, UI transform 제거. 위 표의 모든 값은 이 모드에서 대체된다.
- 휠·마우스 흔들기·화면 가장자리 자동 이동 없음.
- 모든 모션은 UI state change 로 시작하는 render-only 다. 모션은 시뮬레이션·저장 상태를 쓰지 않는다.

## 2. 확정 순서 — §0-10 정정 `[C4-F7]`
이전 판의 "**상태가 먼저 확정** → 결과 텍스트/소리 → 선택적 장식모션"은 `interaction-rules.md` §0-10("확정은 저장이 성공해야 확정이다")과 모순이었으므로 폐기한다. 정정된 순서:

1. **확정 입력 릴리스**(§1-1 기본값 `two-step`, 홀드 없음) → **렌더 ack 은 1프레임 이내 목표**: 버튼 눌림 상태 변화만. 이 단계에서 결과 텍스트·소리·도장은 없다.
2. **`SavePending`**: 아래 §3 진행 표시. 화면 값은 후보(candidate)이며 권위가 없다.
3. **저장 영수증 도착 후에만** 결과 패널(180ms) · 확정 사운드 · 도장/봉인 모션이 재생된다(`animation-contract.md` 와 동일 규칙).
4. **저장 실패**: 성공 연출을 0회 재생하고, 화면은 확정 이전 상태를 유지하며, `재시도 / 뒤로` 두 선택지를 문장으로 제시한다. 되돌리는 모션(성공 연출의 역재생)은 없다 — 애초에 재생하지 않았기 때문이다.
5. 지연 완료 콜백이 화면을 떠난 뒤 도착하면 그 화면의 장식 모션은 재생하지 않는다.
- 완료를 색·동작만으로 알리지 않는다(§0-7). 문자 라벨이 항상 함께 선다.

## 3. `SavePending` 진행 표시 규격 `[C4-F7]` `[TARGET]`
- **잠그는 것은 중복 확정 하나뿐**이다. 되돌림·설정·힌트·증거함 열람 입력은 계속 응답한다. 전역 입력 잠금·전체 화면 스피너·모달 차단막 금지(`animation-contract.md` L24-25 와 동일).
- **표시 위치**: 확정 버튼 자리에 인라인 진행 표시(라벨 「저장 중」 + 불확정 진행 인디케이터). 화면 중앙 오버레이가 아니다.
- **등장 지연 120ms**: 저장이 그 전에 끝나면 진행 표시를 띄우지 않는다(깜빡임 방지).
- **최소 표시 400ms**: 한 번 뜨면 최소 400ms 유지 후 사라진다. 사라짐 → 결과 패널(180ms) 순서.
- **1,500ms 초과**: 「저장이 늦어지고 있습니다」 문장 1줄을 같은 자리에 추가한다. 문장 추가 외의 애니메이션 변화는 없다.
- 진행 인디케이터는 저감모션에서 회전 애니를 멈추고 정적 라벨만 남긴다.

## 4. 홀드 확정 모션 — §1-1 대조 `[C4-F7]`
- `two-step`(기본)에는 홀드 진행 링이 **없다**. 이전 판이 홀드를 전제한 타이밍을 두지 않았음을 여기서 못박는다.
- `hold`(opt-in)일 때만 확정 버튼에 진행 링이 생기며, **링의 길이는 옵션 값(0.2~1.5초, 기본 0.4초)을 그대로 따른다** — 모션이 고정 ms 를 갖지 않는다.
- `confirm-dialog`는 대화 1회를 §1 「기록 서랍 180ms」와 같은 곡선으로 연다.
- 손을 떼면 링은 즉시 0 으로 되돌아가고 명령을 발행하지 않는다.

## 5. 포커스와 소유
- 입력 포커스: 전환 전 id 저장 → 다음 화면 첫 요소 → `back` 복원.
- offscreen·일시정지 애니는 중지. 타이머·리스너는 화면 소유 스코프에서 dispose.
- 공통 RAF 또는 Unity Timeline/Animator 중 **한 표면만** 모션을 소유한다.
- 컨트롤러 confirm 연타로 다음 창을 실수 확정하지 않도록 release latch(§1 「입력 릴리스 래치」와 동일 규칙, 중복 정의 아님 — 인용이다).
- 추론 틀림은 경고 폭발 대신 「시간 기준이 다릅니다」 같은 근거 피드백.

## 6. 한계
- `[TARGET]` 만 있고 `[OBSERVED]` 는 0 이다. 입력 지연 예산·프레임 타임·저장 완료 200ms 목표 중 어느 것도 측정되지 않았으므로 G4/G6 근거로 쓸 수 없다.
- 측정 요구: 확정 릴리스 → 렌더 ack 프레임 수, 영수증 → 결과 패널 시작 지연, `SavePending` 등장 지연 120ms 의 실제 분포. 캡처 도구는 아직 없다(systems 레인 프로브 필요).
